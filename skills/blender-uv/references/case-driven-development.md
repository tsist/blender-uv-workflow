# 从案例学习进入 UV 开发

适用：已有方法被真实工作反例质疑，或新需求需要改变插件、CLI及工作流。它与[学习准备](learning-and-readiness.md)衔接；不要求每次普通UV编辑另建工程流程。详细依据在本地Wiki `procedures/uv-domain-learning-and-production-readiness.md`，本次审计 `F:/Blender AI/runtime/audit/uv-plan-audit-20261113-v001/REPORT.md`。

## 先确定工作，再决定代码

写一张短工作单：**谁在什么用途处理哪个输入 → 哪个案例支持做法 → 现入口能否完成 → 预期行为及反例 → 具体修改位置 → 实际产物与分项验收**。案例要改变接缝、消费者分组、预算或验收中的至少一个决定；只附资料链接不算结合开发。

- 模型资格按当前问题判断。局部连续性可先用有来源的可编辑游戏拓扑与新棋盘；已有贴图迁移需要真实消费者；姿态检查需要可动绑定。新建无UV资产不因没有旧贴图被永久拒绝，明确新消费者即可。研究用商业原数据不自动授权修改/分发；遵守每份资产已核权利与只读约定，不用“商业”二字推断所有权限。
- 实际游戏原布局解释生产取舍，最小折面/平面隔离工具机制，真实候选证明可用性。三种证据各有用途；不得用任何一种替代另外两种的结论。
- 优先组合现有公开操作。缺少一步式入口不等于底层能力缺失；先验证操作链是否满足工作，再决定新增编排或核心算法。新增接口也必须维持已确认约束语义。
- 可复用原则不强制每领域增加插件功能。已有工具够用时交付验证过的工作流；遇到具体失败再修相关实现。研究UDIM/Trim/lightmap不扩大本期制作范围。

## 两个已经改变开发决定的例子

**手部过碎 → 先修切缝意图。** BG3/RE3显示连续手和分指布局都存在，不提供统一岛数。插件旧版却在人工展开前按55°暗加缝。90°折面公共回归证明“2岛且数值pass”的反例；0.7.1将角度加缝限制到自动方法，两人工方法恢复1岛，显式切开为2岛，保持连接为1岛。源保护和独立重开均验；角色手部的连续性、棋盘及姿态仍要在合格输入上另验。

**重点像素 → 先区分规则、操作与预算。** 线密度2倍约需4倍像素面积，这是量纲关系，不是角色通用倍率。生成器没有逐区域计划；`settings`不移动UV是有意设计。现路径是候选→完整岛目标→显式`edit density`→`pack(scale=false)`→完整目标检查/用途配方。逐岛目标、岛内渐变与相对预算是不同能力，不得为鼻眼重点强制切碎脸。若固定绝对目标装不下，保留失败，不暗中缩小；若需求允许统一调整相对预算，须先明确语义并另验。

该链已在0.7.1公共入口用三个等面积平面岛实际验证：默认409.6、重点819.2 px/m；只设置目标时UV未变且正确报fail；显式密度编辑、`scale=false`排布与`CONFIGURED_TARGETS`后通过，独立重开保持。见同批 `PUBLIC-DENSITY-ACCEPTANCE.json`。这只证明组合操作可用，不认证角色预算、自动区域识别或岛内渐变；不把示例数字当制作标准。

## 结束返工循环

1. 复用仍适用的研究和运行证据；看实际输入、消费者、版本和差异，不按迭代编号全部重跑。
2. 实验修复在独占副本通过后，审核差异并合入实际源码；公共入口验证受影响行为，GUI交互改变再补实际交互。不能让修复长期只存在研究目录。
3. 每条证据标明输入、实现、入口和范围。源码运行、旧包隔离安装和技能文档不是同一交付身份；只重验受影响路径及最终精确包必要检查。
4. 已过期的下一步/风险从当前WM移除，历史原文保留；每个缺口归到一个当前工作单。阶段“部分完成”写具体缺项，不反复重建已成功能力。
5. 输出分别记录数据保护、约束/数值、布局棋盘、姿态、下游、用户基准。未知留未知、失败留失败；不能用新摘要把用户拒绝的候选改成通过。

研究完成的出口是“足够支持下一决定”，开发完成的出口是“真实入口产出可用结果”。11领域学习队列继续逐项推进；当前M5交付只依赖受影响领域已就绪，全部追加目标完成前不归档总WM。
