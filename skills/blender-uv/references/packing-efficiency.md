# 排布效率：物理间距、分区与可用细节

用于低净覆盖、细碎岛或细节预算质疑。详细实证统一维护在 Wiki `procedures/uv-packing-efficiency-and-physical-pixel-gaps.md`。

## 同岛折叠与微岛分开修

同岛正面积折叠不是padding问题。0.8.6的`SMART_REPAIR`先完整检查每chart，仅在共享UV顶点的开放边界扇上，选可真实分离交叠面种子的dual桥边，独立自由边界ABF重展受影响chart；好chart不重解。只看最多16条展示例会漏坏chart；预算耗尽不是零交叠。固定旧轮廓的relax/unwrap不适合修边界本身回卷。该方法会增加岛数，不能兼称碎岛优化；复杂非fan结构明确不支持。

微岛先按真实3D邻接分类，区分独立小件与同一连续表面的过切片。后者可选成熟atlas分区，再将小chart与相邻大chart合成完整域，释放内部旧缝、自由重展、保持合并域原面积后联合pack；每组及最终全表面都须以零正面积相交精检。不要用局部相交面积容差代替零判定，不因很小而删面，也不能只提高图幅或改变计数阈值。

本机P02完整12000tri/同2K：原149岛89个<64px² → 已有xatlas66岛17个 → 3D邻接合并8组后49岛0个，净65.2348%→69.4051%，p95 1.00943/max1.87905，gap17.288px。源及旧UV保持；64px²是本例诊断值，不是行业通用门。微岛流程已有`merge_api.py`受限原型（显式输入身份、existing-atlas/可选xatlas、约束拒绝及独立full_check），外层个案CLI仍绑定P02，尚未作为公共`edit`命令；不要与公共`SMART_REPAIR`混为一个全自动方法。证据 `runtime/audit/uv-residual-repair-20261116-v001/p02/` 与 `public-auto-final-jobs/`。

先固定用途、图幅、完整面域与最低gap/border，再分开诊断：

1. 对比请求与实测最短岛距、图边。过量padding先修换算，不能把检查下限一起减小。
2. 按对象/语义域统计净面积、岛数、单面岛、边界周长与实际短边像素。很少面积承受大部分岛数时，先查是否把细侧面过度切断；只报总利用率会掩盖亚像素寻址。
3. 同cuts重排是间距/装填对照；改变接缝、区域预算或复用是另一组对照。少岛不必提高覆盖，也不保证小面清晰。
4. 盒状重复件可先在代表件验证连通展开，再按可靠拓扑计划扩展；接缝树无环不证明岛内无重叠。复制/复用须核实对应和用途，独特损伤需求保留寻址。
5. 按面重复累计面积不能充当复用后的唯一纹理净覆盖。密度放大和形变、过滤、实际笔画清晰度分别验；没有跨资产通用80%等门。

Blender5.2.1已验：原生FRACTION在全自由岛时，两自由边间约为2倍allowance；选中锁岛对自由岛可只有1倍。UV0.7.5共用换算在全自由时除2、有选中锁岛时保守不除2，保留总计1px安全量；这只是求解提示，最终仍查实测gap。混合锁/自由可能有超量间距；edit内接方形尚未充分用长方图长边，原生外边留白会叠加请求border，字段是下限。

未选岛不保证参与原生障碍；未选pin存在本身不证明走锁岛分支。三方块partial反例中，所选间距17px、未选精确保留，却与未选岛意外重叠，完整检查保持fail。显式复用代表/alias恢复同样须实测，不照推断改flag。

本机D06同输入472岛：38.30%→54.54%，实测gap34.47→17.41px，完整1392tri零硬错误、双求值与重开通过；不是全车或引擎批准。60盒状件独占连通展开另降300岛，不能据此声称覆盖再提高。证据 `runtime/audit/uv-efficiency-20261115-v001/`。

中间UV若要等待公共pack，可保留明确quality fail的重叠副本；不要把细小chart平移到很大的坐标来避开中间相交，大量平移会浪费float32有效精度。任何中间策略都不得冒充最终合格结果。

若布局已数值通过，但薄面不足纹理采样宽度，继续按[薄面实际图像消费](thin-surface-sampling.md)检查；实际PNG的DC/纹样、位深、插值和独特标记消费分别验证，不用程序棋盘替代。

完整建筑含大量重复瓦、砖时，先查组件连通性、原seam和chart数，避免将每个小面都当独特绘制域。能否复用由实际材质与独特损伤需求决定；不能直接叠岛。分图集须逐页记录对象、图幅、实际密度和最小岛尺寸，同时报告总像素预算；不同页分别检查，不混算交叠或把覆盖百分比相加。

苏南补充静态建筑（2026-11-16，UV0.8.1）的全页4K为32,977岛/6.21%；拆为主体2K＋两侧屋瓦各4K后为10.08%/19.65%/19.65%，总地址像素2.25倍，仍不足作为高效排布。三个基础页均pass，但主体BEVEL后26无效UV/9负向，两屋瓦双模式通过；问题定位到两块门把手底板。该反例要求在扩大制作前检查代表小件的实际修改器表面，不证明Blender通用故障或该静态资产已获生产批准。证据与同机位图：`runtime/audit/uv-scene-intake-20261116-v001/`；详细结论回收至上述Wiki条目。后续优先评估成熟的重复材质/局部独特遮罩路线，不继续全屋独占页参数试排。

用户允许重复材质后，先核实际形状/朝向/面序再按类型制作连续模板；相同顶点数不构成可靠对应。苏南随后分4瓦类/10砖类，22唯一岛共用1K页，净38.23%；已映射3434瓦与821砖，真实纹理连续性可见改善、保存冷读角点exact。覆盖率只统计唯一模板。公共模板双模式通过不代签全实例：砖倒角近景拉伸仍在；数千别名的已声明交叠仍受当前逐对测量预算限制，须保留未认证，不能靠TILED、删别名或改统计口径放行。当前入口见本批`REPEAT-STAGE.md`，全屋v003；早期缺场景副本只留诊断。

后续0.8.2已闭合本例基础网格的完整复用检查：精确三角坐标＋layout等价类保留numeric岛计数，用组合数恢复原始pair；不跳过同岛折叠、第三岛或不同layout相交。每数值岛的边界先核存在，再去重同layout的精确端点；settings缓存仅单次解析，不跨UV变化。真实188420tri/11123岛在相同50000工作预算下，由旧unknown变完整pass：78473148正交叠全为declared，0未声明，gap17.20396px；原UV/pin、源和非目标保持。`checked_pairs`是几何类计算数，原始pair权重另报；面积不承诺旧浮点顺序bit exact。此修补不解决完整求值复用/砖倒角近景，不升级整屋生产批准。详`runtime/audit/uv-reuse-scaling-20261116-v001/`及上述Wiki条目；旧逐对限制段为历史反例。

同形状类型内仍可能因磨损/尺寸差产生共享密度偏差。先把**全部实际实例**的每chart面积和px/m映射回layout单元，比较该组最小/最大密度能否在现有容差内共享一个统一scale；不能则分类型或取消该组复用。可行时，在每组的允许scale区间内分配预算，并以平方scale加权保证完整物理表面参考密度不被暗改；再一次保比例pack，最后仍以全实例实际数值验收。模板平均密度通过不能代签所有实例。

苏南最终倒角页的首分配为全15228岛最大偏差6.685%，保持失败。按实际48组＋24独立chart推导一次预算，既有5%合同/全分母不变；最差组不可消除的共享偏差约4.731%，故可行。平方区间插值保持原始总像素面积，随后原生pack统一缩放；实际最大偏差4.74179%，332916tri完整pass。72唯一域净覆盖50.12084%，图边16.50px/gap17.00px；不再把旧22基础chart/38.23%的页当最终倒角实证。字段是下限，额外图边与分片开销如实报告，不为总覆盖率再盲目重排。源、原UV保留；主体239对象原2K页、两底板独立页分别检查，5%达标仅指本次三大重复目标。详`uv-final-surface-20261116-v001/REPORT.md`和Wiki原复用条目。
