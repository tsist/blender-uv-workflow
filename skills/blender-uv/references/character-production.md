# 角色 UV：先定义采样任务，再切开表面

本流程用于可编辑、实际游戏拓扑的角色。雕刻高模可作烘焙源，不能替代最终游戏网格的拆分实证。它给出制作决策与验收方法，不把某个 AAA 模型布局当全行业强制模板。

资料与本机实证见[角色证据索引](character-evidence.md)：材质/图集以E01、E03、E05、E09及RE3原引用为依据；预算与位置以E02、E04、E10为例；缝线/绘制与毛发以E06、E11、E12为参考；过滤和多UV用途以E07、E08为依据。部位表是有边界的综合候选，不是照抄某个工作室的统一模板。

## 1. 第一性原理与规则等级

UV 是表面到二维采样域的映射。目标是在给定屏幕尺度、纹理预算、着色器和动画条件下，使纹理稳定、可绘制、可维护。切缝降低某处展开畸变，却增加不连续边、边距成本、法线/过滤风险和绘制接续成本；少岛与低拉伸都不是单独目标。

把决定拆成三层：**切哪里**决定表面连续性与畸变；**分多少像素**决定各处可表达的细节；**放在哪张图及哪个位置**决定实际采样内容、复用与资源生命周期。三者互相约束，却不能互相替代：增加碎岛不能补足像素，合进一图不自动合并材质，把脸移到图中央也不会增加清晰度。

规则分三类：

- **硬要求**：非目标保护、有效采样数据、约定独占域无意外重叠、显式约束、消费者绑定正确，以及本次用途已明确要求的烘焙/交换/视觉条件。
- **有条件的技术要求**：例如过滤/烘焙扩边可能跨岛污染时需要相应间距；切线法线烘焙的硬法线断点通常需要UV断点及padding；方向纹理需要维护方向；它们必须写出触发条件。
- **设计选择/工作室惯例**：几岛、脸放左上或中央、是否独立头图、多少px/m、统一密度还是重点分配、是否镜像。没有项目或用途依据时不能升级为硬门。

## 2. 开工前生成一张消费关系表

每个部位/面域至少记录：

`对象与面域 → 材质槽/真实材质 → shader用途 → 每张图的资源/输出文件 → 所用UV层及缩放/偏移/旋转 → W×H/地址模式 → 独占或复用 → 动态替换/LOD/可见组 → 证据状态`

从实际节点/导出材料/引擎合同读取。Blender活动UV、材质名称、文件后缀和UV0/UV1编号均不能代替消费链证据。过程纹理/世界坐标/三平面可能不消费该层；法线、细节、损伤、遮罩也可能各用不同层或变换。未知消费者保留原层并报告unknown，不盲目重排。

实际入口先用`uv inspect`报告中的`consumers`读取对象、材质槽、图像节点、binding/layer、extension、unknown_bindings与inactive_images。当前报告不能替你提供所有图像实际W/H、文件资源身份、输出atlas规划或任意shader变换；需要从对应已用图像/节点/引擎记录补齐，不能把“层绑定resolved”当成完整采样链已知。非身份Mapping等未解析绑定按unknown处理。

区分：物体、材质槽、shader材质、Painter Texture Set、UV层、UDIM图块、输出纹理集合、联合排布组。它们不是一一对应。Painter按材质分出的制作集合也不自动等于最终游戏atlas。一个材质能用多图/多UV；不同材质能共享同图；不同独立图的UV各自占满0–1不构成相互重叠。

**排布/冲突检查域**按实际共享的输出图及其映射定义，不能只按材质槽分开。两个不同shader若采样同一atlas，仍可能需要联合排布；同图且故意复用则登记面域与用途。共享atlas不自动授权合材质，也不自动减少drawcall。

已有纹理实际消费该层时，岛位置和朝向通常是外观绑定。移动、缩放、旋转、镜像或换UV层前，先判断是否证明采样等价（例如常量或满足周期的平移）；无法证明时，要么只创建未采用候选，要么有明确贴图迁移/重烘焙方案。切线法线图不能当普通颜色图随意旋转粘贴。

## 3. 同图还是分图

按资源生命周期和需求分组，不先按解剖部位强切：

| 情况 | 优先比较的方案 | 代价/检查 |
|---|---|---|
| 近景脸/表情细节明显高于身体 | 头图独立，或同图提高面部密度 | 额外资源与材质成本、颈部边界、streaming mip与色差 |
| 固定整套衣服与少量裸露皮肤 | 可共享一图但保留不同shader材质 | 跨材质联合重叠、atlas更新范围、不同SSS/alpha处理 |
| 可换装/可卸装备/角色共用部件 | 按可替换组件或共用资源分图/复用 | 组合变体、隐藏面、装配边界、重复内存；不默认每件单图 |
| 眼球/角膜/睫毛/头发 | 先按shader、透明度和特殊映射研究 | alpha mip/coverage、根梢方向、眼球折射/泪线；不能套皮肤独占模板 |
| 布料/皮革大尺度重复细节 | 独占底图/遮罩＋平铺细节可能更合理 | 主UV与细节UV/变换分开；宏观图案和纤维方向同时验证 |
| 同材质但近景精度/替换周期不同 | 比较独立输出与同atlas保留区域 | 同材质也不强制同图；项目引擎成本实测 |

头/身体/手/衣服没有固定必须分图数量。不要因“3A”就自动要求UDIM；本项目UDIM仅识别保护，不制作。

### 材质内容怎样改变拆分

| 实际消费内容 | 对缝/布局的影响 | 必须观察的结果 |
|---|---|---|
| 皮肤底色、雀斑、血管、妆容、纹身 | 主要脸/手绘制区保持可接续；独特细节限制镜像；头身可分图，裸露且设计上连续的颈部要接续 | 正脸/侧脸/可见颈部/掌背近景；同皮肤跨缝色调、细节尺度；SSS外观交材质流程 |
| 毛孔/细织纹等平铺细节法线 | 主图独占布局不能说明细节尺度；细节UV/缩放/混合遮罩分别保护 | 缝两侧颗粒尺度与流向，近景及mip下闪烁；不得只看base色棋盘 |
| 条纹/格子/印花布料、带方向皮革纹 | 接缝靠裁片结构，方向和图案相位进入锁定条件；同一平铺图也可能需要不同方向变换 | 衣缝两侧图案按设计接续，经纬/纹路不被pack旋转破坏 |
| 烘焙切线法线、硬表面护甲 | 接缝与硬法线、三角化及烘焙边距关联；连续光滑皮肤UV缝不要反向强制硬边 | 一致TBN/三角化下的高光、法线缝与镜像手性；只见base色不能批准normal |
| Roughness/各向异性/拉丝 | 小误差可能在掠射高光显露；各向异性方向可能来源于UV切线或专用方向场 | 换光/转视角；核方向场实际来源；单纯岛形规则不保证高光连续 |
| 眼球、角膜、泪线、透明发卡 | 独立shader/特殊采样/alpha允许不同布局与复用；小岛或图幅外UV未必错误 | 先查实际通道与映射；眼球方向、根梢、透明边/mip；不套用皮肤独占规则 |
| 动态污渍/损伤/纹身模板、换装色板 | 可能锁定UV模板/区域或要求另一独占层；不能只保basecolor那一层 | 改布局后相关遮罩/区域仍对应；LOD/组件变体独立核验 |
| 高度/置换 | 表面和轮廓对接缝/密度更敏感；求值表面与基础网格不同 | 实际渲染器置换另验；现有capture-engine表面报告不认证像素或置换等价 |

这些是由消费内容推导的检查方向，不是为每种物理材质强制一套岛数。颜色/粗糙度/金属度打包进RGBA也不意味着需要4套UV；通道打包与UV通道是两件事。

## 4. 面积、比例、位置和方向

线性纹素密度与分辨率和表面积有关：固定同一图像和UV层、无额外UV变换时，某域的面积平均密度可用 `sqrt(W×H×Σ|Auv| / ΣAworld)`，world面积需包括对象变换和单位。分子分母必须覆盖同一面集：有意堆叠也逐面累加UV面积，不能分子去重、分母仍累加全部表面。它是面积均方意义的概括，不说明局部各向异性、最差三角或唯一像素预算；后者要另算复用后的覆盖。非方图/非等比UV变换要在像素空间检查两个方向；不要只拿一个面积数判断拉伸。

不要把上述面积密度直接称为最近机位的“1:1清晰度”。需判断短方向采样时，用实际相机局部微分 `J = d(screen_px)/d(UV)`，最低texel/屏幕像素关系为 `1 / σmax(J × diag(1/W,1/H))`；方图可写 `W/σmax(J)`。正交视的平面三角可直接求仿射，透视视角需注意实际位置的微分与遮挡。数值1只是局部采样关系，不是纹理保真或视觉通过线。已过约定畸变门的岛做统一放大不会改变其内在畸变，不能另造更严的ratio筛选线排除真正低采样区域；预算优先级仍依据实际可见特征、采样与本次用途。

拆包或分析工程的unit_scale=1不证明原资产经过米制校准；未校准时报告px/native unit或明确的场景单位假设，不能冒充px/m行业基线。

- **预算分配**：同密度时UV面积按世界表面积分配；某区域线密度提高2倍，像素面积约需4倍。脸/手/徽标是否加权由近景画面、第一/第三人称、细节频率和可见性决定，不能写固定“脸占25%”。
- **跨图比较**：先乘W×H再比，4K图上相同UV面积比2K获得4倍像素面积。运行时只驻留低分辨率mip会降低最高可用密度；实际采样哪级mip还取决于投影导数、过滤和偏置。文件最高分辨率不等于当前驻留或当前采样精度。
- **屏幕预算**：按实际最近镜头、画面分辨率和表面方向检查局部投影；倾斜表面的两个方向缩短程度不同，不能用单一cos角度公式签核全表面。局部方向纹素密度乘物理长度得到纹理texel数，不是屏幕像素数；屏幕覆盖须由相机投影计算，两者比较才能评估采样需求，面积平均密度也不保证各方向精度。近景欠采样可能已经是在放大mip0；远景缩小采用低分辨率mip是另一问题。UV线尺度与纹理边长同时加倍会使线密度变为4倍，不会相互抵消。
- **同档一致**：比较同用途/相近可见区域，允许已声明重点区域、内侧/口腔/底面降低预算。不能用全角色平均把指尖/眼周欠采样掩盖，也不能把艺术加权强行拉平。
- **位置**：未绑定纹理且无atlas模板时，岛放角落/中心本身不提高清晰度；优先可读性、间距、满足预算和后续编辑。唯一覆盖率可辅助比较，但没有统一最低值，不能牺牲padding或方向锁定来填满。已绑定纹理、模板、固定区域、UDIM或shader偏移时位置有语义，必须保护或证明变换等价。
- **平铺相位**：REPEAT下整数纹理周期平移可重复同一采样；任意小数平移仍会改变图案落点。若有UV缩放/旋转，周期要在变换后的采样坐标中判断；不能把“平铺”理解为可随意移动已有花纹。
- **方向**：布料经纬、拉丝、皮革纹路、毛根到梢、文字/纹身/徽章各有要求。把方向约束锁定再pack；不能为了更满而任意转90°。没有方向需求也不必强行所有岛朝上。
- **比例**：等比缩放保持岛自身角形；非等比压扁用于填空会改变细节比例。允许变形的特殊设计须有视觉依据，不默认放行。
- **padding**：岛间空隙、图边空隙与烘焙/导出的像素扩展是不同项。按最终输出尺寸、最低相关mip、过滤/压缩设置观察边缘，不把2K的固定16px推广到所有引擎。降采样L级时基础间距约缩为原来的1/2^L，仅是预算估算，不能代替渲染检查。

### 预算重排与清晰度验收

1. **先定面集和用途。** 正脸、完整头岛、躯干、四肢、双手分别用明确面索引或可复查选区定义；名称不互相替代，只有互斥面集的占比可直接相加。重点面集小于整岛时，说明是接受整个岛的像素成本，还是另行处理局部映射；不能将完整头岛的面积当正脸预算。没有实际五官的基础网格不能认证眼睑、鼻翼或嘴唇质量。
2. **分开三种面积口径。** 在有效、无重叠、图内的独占布局中，净覆盖是 `Σ|UV三角像素面积|/(W×H)`；它不含padding。存在声明复用时，逐面面积和与唯一并集分别报告，不能用前者冒充占用率。全部岛的轴对齐包围盒是粗略外框，不能当净覆盖；边距另报图边/岛间最小值，需要含padding占用时须另定义测法。固定图幅且岛面积不变时，平移/旋转不增加净覆盖。低覆盖触发用途与容量复核，不自动等于失败，也不以固定80%等比例作为所有资产门槛。
3. **在操作前选择预算策略。** 绝对密度固定时用`pack(scale=false)`，容量不足则保留失败，比较有理由的排布/图幅/分图方案；一次失败不能证明更小图幅数学上不可行。用户要求增强某部位时，先改区域预算再排布。明确采用“区域比例固定、图幅内统一缩放”时可用`pack(scale=true)`，先记录比例及适用的绝对预算上下限，再测实际缩放系数、每区密度、边距和溢出；不得把缩小低于下限的结果静默采用，也不以事后实测值回填目标来证明预算合理。旋转/缩放仍受已有图案、方向、pin和消费者约束。
4. **区分容量与清晰度。** 更多纹素允许表达更多细节，但不消除原有局部各向异性。全岛等比放大保持局部形状畸变；局部两主方向的尺度、最差面与屏幕投影仍需检查。头/躯干近景要用同一模型、相机、输出尺寸、纹理内容及过滤方式作旧/新对照；棋盘随密度变细只能证明采样分配变化，不能独立证明真实图案改善。需要诊断时，将同一模型空间细线/点阵通过各自UV栅格化到实际图幅，再由图像纹理采样渲染；直接程序纹理绕过UV、只给新版本更细图案或改机位不构成公平比较。合成图案改善不外推真实皮肤、完整动画、游戏mip/压缩已通过。
5. **明确有效规格与维护目标。** 操作请求默认W/H、候选`record.manifest`、settings绑定、实际图像消费者和导出规格分别核对；不能拿2K请求值解释4K结果。尺寸变化保持绝对密度时，UV线尺度按分辨率反比调整（方图2K→4K时各轴减半），再重绑并测量。当前`copy_uv`不继承原候选的区域settings；新候选未配置时可能因默认均匀密度检查而fail，先看硬检查、具体违反项及事前意图，再显式配置区域规则，不能修改容差掩盖重叠/退化。比例填图后固化实测维护目标只为防止后续漂移，预算下限、比例、画质和用途必须另外有据。

源/非目标保护和保存重开仍沿现有流程执行；保留旧渲染UV不等于新材质已消费新层。导出游戏时另核UV层名→导出通道→引擎材质的实际映射。以上规则补充制作决定和测量口径，不新增重复审批，也不强制无相关用途的项目完成所有下游流程。

## 5. 全身接缝的候选技巧

先观察原拓扑与主要视角，标出必保连续区、方向区、现有材质/几何边界、动画关节及真实缝线；再提出少量具有明确取舍的方案。以下是候选位置，不是强制模板。

| 区域 | 连续性优先与常见切口 | 主要陷阱/验证 |
|---|---|---|
| 正脸/头皮/颈 | 保眼鼻嘴附近主表面可连续绘制；后脑、发际隐藏区或颈部结构边界作为候选 | 脸中线不轻易切；表情张嘴、鼻翼/眼睑角、颈头跨图密度与颜色接续 |
| 耳/鼻孔/嘴内/牙舌 | 强曲率或独立组织可单独开岛；嘴内依据实际可见与精度安排 | 不将牙齿/口腔的小岛算成“脸被拆碎”；耳背缝在侧面可见，张嘴会暴露口腔 |
| 躯干/肩腋 | 躯干侧/背侧、腋下等低关注区域作为候选；考虑衣领/真实衣缝 | 腋下不是永远隐藏；抬臂、扭腰检查条纹/棋盘变化，不能按每个骨骼机械切开 |
| 上臂/前臂 | 沿内侧或相对低可见路径纵向切开，关节附近保持可控连续 | 第一人称前臂可成为重点；扭腕/屈肘检查纹理流向，避免短小横向碎段 |
| 手掌/手背/指蹼/手指 | 比较掌背主岛、连指方案与有依据的独立指岛；接缝沿侧面/指侧低关注线组织 | 指蹼与拇指根拉伸、掌纹/手背识别、握拳/张指、手腕接续；绝不以“每手必须2岛”验收 |
| 指甲 | 独立岛便于方向/精度/材质，连续也可按需求 | 不把合法指甲岛等同于过度碎裂；甲缘padding、重复与独特损伤 |
| 臀/腿/膝 | 裆内/腿内或真实裤缝为候选，按可见与服装决定前后片 | 坐姿/屈膝/蹲姿和裆部；不要在膝周任意环切以降低数值 |
| 足/鞋靴 | 鞋帮/鞋舌/鞋底/鞋跟按构造与磨损组织，裸足考虑足内侧/足底 | 鞋底并非永远不见；步态和蹲姿；左右标识/磨损不应自动镜像 |
| 衣服 | 沿实际裁片/缝纫结构有助纹理方向；主可见图案尽量连续 | 真实衣缝不必全部切；纹理经纬与接缝两侧尺度要合理，图案跨缝按设计对齐 |
| 护甲/首饰/背包/皮带 | 硬表面构造、遮挡边、涂装面/标志及法线烘焙约束共同决定 | 材质边不必然是UV边；硬法线断点与UV seam不能互相等同；带条拉直需检查面积/方向 |
| 头发/眉睫/毛发卡片 | 按atlas条带、根梢与透明轮廓布局，可有意复用 | 不按皮肤的无重叠规则误杀；alpha边缘、覆盖率、mip、双面、梳理方向需要专门验证 |

手过碎时先定位生成机制和消费用途，再修改接缝。不能用“低拉伸”掩盖数十个无语义指节碎片；也不能只缝成两岛就宣布工业合格。BG3与RE3的不同原手布局/不同通道已经反证统一岛数规则。

局部拉伸修正先定位最坏三角及其连续UV节点，核对固定边界与可动内部点。`relax/unwrap`的求解目标不等于逐面最大各向异性：整手重解可能改善原坏面，却把更大畸变转移到指尖。遇到这种有证据的取舍，可从未修改基线选取问题节点的完整同UV侧一环，用`FACES`固定周边后做有限局部对照；不要跨缝合并同网格顶点的不同UV别名。检查全部受影响邻面和全手最大值、非目标精确保护及实际图像，记录哪些面变好/变差；仅指标pass或原坏面下降均不足以采用，不靠增加迭代反复碰运气。当前局部入口固定岛/面片边界，不承诺自由改轮廓；需要改轮廓或接缝时另提有依据的候选。近景还须确认问题表面实际可见，遮挡区的像素不变不能证明该处改善；数值改善但实图差异轻微时如实保留结论。Orange限定实证见`runtime/audit/uv-hand-refine-20261114-v001/REPORT.md`，不推广其面号、移动量或改善幅度。

独立指岛需要同时规划根部分离环与至少一条合理纵向开口，检查切开后的角点拓扑；不要只按骨骼权重阈值选面。最坏三角可能自然留在掌侧，因此新边界附近的剩余掌域也要参与求解，不能锁住原掌UV后仅解拇指。保持同一手部总面积预算时，可按各新chart的世界面积分配，再以整岛刚性排布避让固定非手区域；单选移动岛不保证其余岛作为原生pack障碍，最终完整相交/图边/间距检查仍独立负责。

新增接缝会改变棋盘相位；用相同表面内容分别栅格化的实际贴图检查采样效果，并以三角内在Jacobian比区分UV畸变、相机投影和清晰度问题。指标改善但同内容画面接近，只能报告所查内容未见明确清晰度收益，不能倒推几何坏或UV完全未改善。Orange分拇指探索中根部比值下降而近景收益不明确，因此未采用、未补齐正式验收；限定记录见`runtime/audit/uv-orange-thumbsplit-20261115-v001/REPORT.md`及Wiki角色制作条目。不据此推广“拇指必须独立”或“分拇指无效”。

## 6. 重叠、法线与形变

- 独特文字/纹身/伤痕/左右差异一般需要独立像素；故意镜像/堆叠需要登记适用图层及实际采样，AO/法线烘焙与动态损伤可能不允许相同复用。相同外形不自动证明可共图。
- 发卡纹理/atlas通道可以共享条带；若要记录每张卡在完整发型中的不同遮挡等结果，烘焙域必须能独立区分这些卡。可用另一UV层、独立烘焙mesh或其他明确映射；独立工作副本仍须保留完整发型的遮挡上下文，不能逐卡孤立烘焙代替。不是所有发卡都需要第二层UV。动态局部损伤同样先查实际独占/投影机制，不能按效果名字强制UV1。
- 常规切线法线管线要核对三角化、顶点法线/硬边、UV、切线基底、镜像手性与目标引擎约定；UV seam不必反向强制硬边。不要在柔软脸/手上为每条UV缝制造阴影折线。
- 原UV有向面积为负只记录映射朝向，不能单凭符号认定布局坏或要求翻V；应结合源坐标约定、实际图像、镜像用途及切线法线采样判断。
- padding解决过滤时的串色，不能修复不匹配的切线基底。烘焙前记录normal通道约定与切线计算方式；不能只凭“DirectX/OpenGL”标签推断完整TBN一致。改变相关UV、法线、三角化或切线计算后，重新核对并按需重烘焙。
- Blender的UV数据存于面角/loop，标记seam或切开UV本身不切断基础网格拓扑。对编译后的游戏网格，UV/法线/材质边界可能已成为重复的渲染顶点；这不等于原DCC网格曾沿缝断开，也不能据此推断蒙皮因果。重建可编辑连续拓扑前须核对来源、角点属性、权重和形态键对应；位置相同不授权自动焊接，所需拓扑修复交建模流程。
- 变形后“格子更长”可能来自真实表面伸展、蒙皮或UV布局，先分别测基础/求值表面。选用途相关的抬臂、屈肘、张握手、屈膝及脸部表情；离散姿态通过不等于全部动画通过。
- UV工具不修骨骼/蒙皮/重拓扑。输入缺陷导致无意义碎裂时精确交接，不以减面删形态键获得假通过。

## 7. 执行与验收

### 先区分信号投影与UV采样模糊

棋盘或模型坐标线条出现楔形时，先用同相机的解析信号作诊断真值，再与该信号经实际UV PNG重建的结果比较。解析真值仍有同一形状，不能继续靠加缝追它；解析图只用于归因，不能代替实际贴图验收。若真正差距是模糊，按像素预算修短轴采样，不把各向异性数字下降说成清晰度改善。

本机Orange在旧返修批次用户重新授权后保16岛/原接缝，提高双手预算并保形重排：实际手线密度×1.4343、像素面积×2.057；同20万点覆盖全部796手tri，4K PNG重建MAE .021028→.011298，同机位点线边缘温和变清。非手密度×.956204、头/躯干实际4049.79/2024.90px/m及全身信号轻退均公开；内在max2.616没有修掉，三有限姿态不代签完整动作。该旧批次当时没有Orange近景max≤2的已批准用途门，不能从P0受控模型移植门槛。证据 `runtime/audit/uv-residual-repair-20261116-v001/hands/`。

后续两项专项的Q8/Q11已由用户单独冻结Orange静置max≤2.0、既有弯指/转腕max≤2.2，并要求真实近景同时改善，4K及非手密度不退；当前任务须沿用该明确约定，不能援引上一段旧状态取消数值门。新接缝与Q14局部预算候选已过相应技术检查，但现有同内容卡通材质近景尚无明确清晰度收益，不能仅凭最大值下降或覆盖率增加宣称专项完成。任务约定与证据入口为 `runtime/audit/uv-two-residual-specialist-20261116-v001/BRIEF.md` 和 `integration/hand-local-budget-review/`；这些数值仍只绑定本输入与有限用途。

1. 确认游戏拓扑、使用场景、真实消费者与原数据保护，记录未明项。
2. 建图集/通道表，给出像素预算、允许复用、方向、锁定区与代表姿态。
3. 在3D上标注接缝理由；展示至少必要的可区分候选，保留原UV。没有必要不凑候选数。
4. 展开前后对比实际切缝集；求解器增加了未声明缝就调查，不静默接受。
5. 先检查连续性与局部拉伸，再按已定优先级分配密度和联合排布；最终pack若自动归一会抹掉重点预算，必须重新实测。
6. 导出各实际消费域的完整布局（常规独占图为0–1，平铺/受保护UDIM按实际范围记录）、3D接缝、带方向字符棋盘、重点部位近景、实际分辨率/密度与代表姿态图。每张图标明输出图与UV层，不能只导出活动层。仅缩略图不够判断指蹼、眼睑等局部。
7. 分别记数据完整性、消费者/约束、数值、棋盘视觉、姿态、烘焙/引擎、保存重开。任一未做写not_run/unknown；新角色用途未审基准不写production pass。

UV专项主要负责布局与棋盘；真实材质、法线、眼发shader与引擎过滤由对应流程交接验收。若任务本身要求这些效果，未完成不能宣布该用途完整通过；不擅自扩张用户已冻结的UV专项范围。

交付至少含：消费表、接缝计划与实图、候选比较/拒绝原因、像素预算、原/新层与恢复入口、分项验收状态和下游待办。报告结论必须与实际文件/通道/版本相绑定。

### 已运行的低模角色接续示例

本机批次 `runtime/audit/uv-development-20261113-m5-v003/REPORT.md` 记录Orange真实输入的当前公共链：人工缝ANGLE_BASED → 整岛settings与density → 保尺度pack → 三个有限姿态surface → 显式UV字符棋盘。它证明这些已有入口可以组成有重点预算的可编辑角色候选，不需要先增加角色生成专用API。

该例2K当前排布超界后，复制候选到4K并把UV各轴缩小至一半，保持原绝对px/m后再绑定、排布和测量；这不是证明所有2K排法不可能。单纯增大图幅但不调整UV会改变密度，单纯settings也不会落实预算。旧4K净覆盖16.36%有大量留白，独立审核只认可原型接续，未批准生产质量。源模型局部轴与世界轴不同，部位筛选须显式转换或使用已确认面域；姿态图从实际求值网格取UV，不能从base副本冒充形变。
