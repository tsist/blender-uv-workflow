# UV 领域学习与制作准备

核验日期：2026-11-13。此处约束学习与判断流程，不认证尚未实作的资产类别。用户明确要求未知领域先学习；已有适用证据可直接复用。详细知识入口：本地 Wiki `procedures/uv-domain-learning-and-production-readiness.md`；领域队列见[asset-domains.md](asset-domains.md)。

## 开工判断：看机制，不只看类别名

将任务理解为“表面与可见组合 → UV 消费者 → 允许的布局变化 → 质量目标 → 交付验证”。角色熟悉但换为第一人称手臂、动态伤口或换装模板，仍可能出现新机制；岩石陌生但只是保留既有 UV 导出，也不必先完成全部岩石制作研究。

| 当前证据 | 下一动作 | 不能做的事 |
|---|---|---|
| 已验方法的输入、消费者、版本、用途与本任务相符 | 核对差异后开始候选；继续正常检查 | 因队列尚未轮到该类别就阻塞成熟工作 |
| 不知道哪张图/哪一层/哪种变换在起作用 | 只读查节点、资源、格式或原管线，必要时做隔离取样实验 | 随意切换 active_render、重排已有图案、把未知当未使用 |
| 接缝/密度方法来自不同领域或未经验证的推测 | 查匹配领域原文和原案例，设计区分假设的实验 | 把自动碎岛或少岛当行业标准 |
| 原理明确，但当前操作入口是否保持约束未知 | 用最小工作副本核实际切缝集、预算和保护结果 | 依据方法名称或旧接口文档保证行为 |
| 候选数值通过，但关键视觉或用途尚未验证 | 保留候选并完成缺项；向用户呈现需决定的具体基准 | 标生产通过或继承别的资产阈值 |
| 一部分未知、一部分已明确 | 暂停受影响的生产动作，继续研究/独立的已明确部分 | 把所有工作停掉，或用无关部分成功覆盖未知 |

只读检查、研究以及有明确假设的可恢复实验不需要新增“研究许可”。当实际需求、资产权利、外发、安装或覆盖权限欠缺时，按真实缺项询问；不能把学习规则变成反复确认流程。

同输入、同用途重做候选时，复用仍有效的来源、消费者和已确认基准；检查新产物但不重走全部研究，不重复请求既有用途批准。公共入口已独立重开并给出有效回执时，不再为了“独立”另开一次进程。旧报告不自动属于新产物，但可以通过有效身份/差异证据复用其适用结论。

将学习转成开发时，按[案例驱动开发](case-driven-development.md)写明确工作单。先核现有组合操作能否解决真实问题；隔离实验通过后接回公共入口。输入资格按当前要证明的事判断：新建UV不要求已有成品贴图，姿态证据也不阻塞独立的接缝机制试验；缺消费者不能签材质迁移，缺rig不能签姿态。全领域学习队列和当前M5交付分别跟踪，不能互相冒充或循环等待。

## 学习循环：每轮解决一个影响决定的缺口

1. **提出问题与可能反证。** 例如“多个材质是否共写同一张图，能否独立排布”，而非泛搜“最好UV”。列出不同答案将改变什么操作。
2. **复用并审查已有知识。** 查本地 Wiki，命中后回读原文；核对来源、日期、版本、样本与未验范围。只加载有关 reference。若新证据否定旧条目，记录替代结论，不能仅给新报告加备注。
3. **补原始资料。** 优先当前工具/格式文档、工作室技术说明、具名制作拆解及实际可核的开源实现；再用社区经验补盲点。记录 URL、实际读到的正文范围、版本/年代、主张与条件。摘要、转载、同一访谈的多个网址不是独立佐证；网页限流/不可读如实记缺口，不绕限或假称全文读完。
4. **选能回答问题的样本。** 说明游戏/管线/角色或资产身份、LOD、拓扑用途、可见部件、UV层、消费者、贴图尺寸、许可与来源。生产低模/实际游戏网格做拆分输入；高模只在需要时做烘焙源。自制可控例隔离机制，真实例检验实用性，两者不能互相替代。
5. **比较有差异的路线。** 按导致决定变化的维度选案例/反例：共享或独立图、unique或tile、连续或重叠、多通道职责、目标视距/形变等。模板相关的多个角色不算多条管线；不设为了凑数的来源/案例配额。
6. **最小决定性实验。** 先给出假设、各自预言、测量口径和失败条件；保留原数据与输入身份，再用隔离副本/最小样本核验。数值正确、原数据还原、棋盘可用、烘焙/引擎外观分别判断。区分力指不同假设能产生可检测的预言差异；实际两方案结果相同，可能否定“其中一个更好”，也是有效结果。只有设计/测量不能区分关心的机制时才改实验，不能为制造差异换样本或靠参数穷举找“通过”。
7. **写条件规则并验证使用。** 用“触发条件 → 制作动作 → 依据 → 验收 → 反例/限制”表达。交给独立任务应用，检查它是否会改变正确的决定；代理复述规则不证明会制作。错误推断回填原条目与技能入口。
8. **双处沉淀并更新 WM。** Wiki 保留详细问题、来源、案例、测量、失败、适用边界；reference 保留执行要点、关键证据与案例摘要，指向同一 Wiki 知识单元。技能主入口仅留硬规则和路由。完成一批后串行同步链接、索引、构图，检索并回读；维护受阻记录待办，不假称闭环。

本机维护例外（2026-11-16实证，memory-lancedb-pro 4.2.0-codex.1）：`wiki_build`的图谱虽为增量，向量步骤仍全表清空重嵌，不能把`force=false`当作只更新当前文章。少量UV知识变更先比对原文/索引，复用已有图谱增量函数及明确路径的定向合并；公共混合/语义检索和原文回读通过后才算闭环。方法、备份和版本前提见Wiki `procedures/memory-lancedb-pro-wiki-build-recovery.md`；本批30页已核当前，未修改插件/配置，也不把共享库其他断链扩大成UV交付门。

## 证据与完成状态

对每领域/关键机制分别记录：`资料覆盖、原案例观察、机制实证、候选制作、独立迁移、用途批准`。每项写已完成/部分/未做/不适用及证据，不用一个“已学会”吞掉差异。执行状态在现有 WM；Wiki 的 draft/stable 是具体方法成熟度，不是用户批准。

**可以开始候选制作**：影响路线的消费者与输入已明确；接缝、预算、布局选择有匹配依据；关键操作已知或经最小实验确认；知道本次怎样发现失败，剩余未知不影响该受限候选的可靠判断。无需先把整个领域百科读完。

**可以结束当前专题研究**：主要备选与取舍有依据，影响下一决定的关键未知已解决，未解决部分有明确限制与验证路线；没有足够证据就保留缺口。来源数、代理数、报告页数、单次指标不作为结束标准。

**可以采用或宣称能力**：另完成输入/数据保护、约束/数值、布局棋盘、用途相关最终表面与姿态、保存重开和适用的下游交接；新用途按既有约定由用户确认基准。成功仅覆盖所测输入与条件；研究、原资产分析或诊断规划不能签发生产能力。

## 记录应足够短，但能复查

复用已有 inspect、作业、来源记录，只补本任务差异即可。复杂新专题可用以下字段，不强迫所有小任务重复填写：

`问题/未知 → 当前证据与资格 → 输入/消费者/单位/图幅 → 备选与反例 → 实验与实际结果 → 条件规则 → 未验边界 → 下一动作 → Wiki/reference路径`。

并行研究按资料、原资产、数学/测量、实际操作、独立审核分工，各有输入/输出、停止条件和独占目录；按资源与限流分批，不为规模堆代理。主线程审原始关键证据，统一矛盾并作最终判断；同一 Wiki/技能/WM 串行整合，不能让多个代理同时覆盖。

## 可复用条件规则示例

- **多个材质写同一图的同一用途层** → 建立同一排布域并联合查意外重叠 → 材质槽不隔离采样坐标 → 查真实资源绑定与UV叠图 → 不同独立贴图中的相同坐标不能当冲突。
- **既有贴图/固定图集/方向纹理** → 保护位置、旋转、比例和相位，或明确做迁移 → 它们可能是采样接口 → 对照实际消费者 → 新建无方向内容的自由图集不受同一位置约束。
- **位置/方向参与函数采样** → 查实际函数和作用域，再判断变换是否等价 → 对称性、常量区域或未作用区域可能保持结果 → 按明确参数/时间范围验证 → 不能声称任意非周期变换必然改变结果，也不能凭少量帧推广到全时间域。
- **重点区域提高线密度** → 按图幅和真实表面积预算像素 → 两倍线密度约四倍像素面积 → 量纲与局部棋盘核对 → 未校准单位不得写px/m；已有角色比值不是其他领域标准。

这些是决策方法，不是新领域已完成证明。真实推导链见[research-cases.md](research-cases.md)。
