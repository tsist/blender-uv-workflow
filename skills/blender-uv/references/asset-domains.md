# 主要游戏资产的 UV 学习路径

2026-11-13建立。执行队列保存在 `wm-2026-11-12-uv-plugin-cli`，详细知识入口为本地 Wiki `references/game-asset-uv-learning-curriculum.md`。本文件提供学习路由和问题，不声称以下领域已经全面掌握。每次使用按[学习与制作准备](learning-and-readiness.md)判断当前机制。

## 先建立共用知识，再按领域应用

共用主线：表面到纹理采样的映射；材质/UV层/纹理集合/图集的区别；表面积、图幅、线密度和屏幕覆盖；连续性与畸变；独占、镜像、堆叠、tile/trim；位置/方向/相位；padding、扩边、mip与压缩；三角化/法线/TBN和烘焙；形变、LOD、变体、交换及数据保护。

先用已核角色案例理解消费者和预算，再在每领域检验哪些原则可迁移。写实/风格化、移动/主机/PC、第一/第三人称、视距、扫描/生成来源是横向条件，不因为名字相似就沿用阈值。lightmap、运行时遮罩等按独立消费者研究，不和主颜色UV混为一层。

## 逐领域顺序、关键问题与实证出口

通常按下表顺序逐个领域收束；真实任务需要可先学习对应领域，说明依赖和返回点。子代理可在当前领域内并行取证；不把同时建多个空目录当作全面研究。样例是选材要求，不代表本机已持有这些资产。

| 顺序 / 领域 | 必须弄清的问题 | 代表性输入与差异 | 实证出口与失败观察 |
|---|---|---|---|
| D01 人形角色 | 全身图集/材质关系；脸、掌背、指蹼、腋/裆连续性；重点像素、独占与复用；多通道用途 | 当前BG3/RE3原案例作对照；制作选可连续编辑的游戏拓扑，保留绑定/形态键；不同模板和消费机制有明确差异 | 接缝理由→实际切缝→预算→局部棋盘→代表姿态→保存重开；不得以固定手岛数签通过 |
| D02 生物、四足、怪物 | 长尾/角/翼膜/足垫、鳞片/毛向、口腔；四足关节与非人类轮廓如何改变接缝；先读[四足制作方法](quadruped-production.md) | Autumn原例可解释原UV与消费者，属于电影参考；游戏制作另选几何合格且消费者明确的网格 | 检验关节/翼膜变形、条纹跨缝、腹侧隐藏与可编辑性；区分皮肤UV、RootUV与方向源；人形手部经验不能直接套翼/爪 |
| D03 服装、护甲、可穿戴与换装 | 布纹经纬/图案相位、内外面/厚度；裁片与UV岛的关系；模块边界、身体遮挡与共享图集；见[服装制作方法](garment-production.md) | 本地T恤已有静态新方向纹样候选；硬护甲/换装仍另选明确输入 | 棋盘/真实条纹、活动关节、替换部件的消费者/布局保持；一个方向锚边不等于整片经纬，缝纫边不强制逐裁片一岛 |
| D04 头发、毛发、羽毛薄片 | 卡片纹理族、root-tip方向、alpha边缘、重叠复用与独占烘焙层；与groom生成UV的区别；见[透明卡片方法](alpha-cards.md) | 有明确atlas与卡片对应的发束/叶状羽片；groom仅在相关任务研究 | 检查条带落点/方向、透明边缘和近远视图；重叠许可按消费者，不把逐卡独占当通用要求 |
| D05 道具、武器、硬表面产品 | unique/tile/trim的用途取舍；硬边/UV缝/TBN；文字、涂装、第一人称视面、重复零件 | 已有P0/沙发仅复用其限定证据；补代表性近景带文字/多部件道具 | 准确三角化/烘焙交接、文字不镜像、边缘/密度/联合排布；不能外推P0数字到全部武器 |
| D06 载具与机械 | 大小曲面尺度差、车漆/贴花/仪表、可动件、模块重复、内外饰、损伤层/LOD；见[载具与机械方法](vehicle-production.md) | 可动门或轮组、独特涂装与可复用机械部件；实际消费路径明确 | 曲面棋盘、涂装连续、移动部件与LOD取样；多个材质不等于必须多张图 |
| D07 模块化建筑与结构套件 | 重复尺度、拼缝相位、trim/atlas接口、平铺方向；烘焙光照/第二层的独立要求 | 可拼接墙角/门窗/梁件组合，对照独占与重复材料路线 | 拼接后方向/密度/接缝、材质变化与光照通道分验；单块看好不能证明组合好 |
| D08 独特环境资产、室内陈设 | 大小部件预算、近景焦点与背景复用、可拆分图集、污迹/贴花、烘焙组织 | 有明确镜头用途的独特建筑部件或室内hero资产，与已有家具证据比较 | 全景与近景联合观察、图集消费者、涂绘接续和资源预算；不是把全场景强塞一图 |
| D09 岩石、地形及自然地表 | 宏观独占细节/平铺细节/三平面等实际映射；扫描重拓扑；地形层混合与接缝 | 近景独特岩石与重复地表两个机制；高模仅在烘焙源阶段使用 | 确认是否真正消费UV、尺度/方向/接边、坡面与LOD；三平面方案不等于UV任务已通过 |
| D10 植被、树木、叶片 | 树皮方向/分叉、叶atlas、alpha轮廓、叶片复用、风动与LOD/远景替身 | 分叉树干+叶片组，并明确风动/远景需求；不是仅一片平面叶 | 树皮连续/尺度、叶朝向/透明边缘、声明重叠、风动/LOD；密度与卡片面积不能替代轮廓和过滤观察 |
| D11 透明、液体与UV驱动特效表面 | 玻璃/水面/流向、翻页纹理、溶解/伤口遮罩、极坐标/滚动；UV是否是算法参数 | 选当前任务真正使用的shader与图像序列，先拆分消费机制 | 实际取样/时间与方向实验；2D布局漂亮不证明动态效果正确，效果验证交给对应材质/动画流程 |

眼部、牙齿、口腔和皮肤特殊层在D01按消费者细分；发卡、布料和甲片在角色总体图集确定后分别展开专题，避免遗漏也避免重复立规范。海面/地形程序化映射若不消费目标UV，写清不适用依据，不能凭类别跳过调查。

## 每个领域都交付什么

在同一 WM 记录当前问题、证据状态与下一决定；Wiki 和 reference 应真正包含：适用用途、原始来源及代表样本、消费者图/预算依据、部位接缝决策、比较/反例、制作步骤、失败定位、验证结果与未验边界。没有资料的领域先保留本路径里的研究问题，不创建一堆空方法文件。

路线图中研究的UDIM、Trim Sheet、lightmap、目标引擎、动态效果可用于解释选择、避坑或提出后续方案；**本期仍保留F01–F28与现有制作能力限制**。知识覆盖、软件实现、实际支持和用途批准是四件事；需要新实现时先明确与原需求的关系，不自动宣布具备能力。
