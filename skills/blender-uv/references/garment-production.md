# 服装UV：布纹方向、裁片与像素分配

2026-11-14；D03静态T恤实例，详细证据与来源见Wiki `procedures/garment-uv-grain-direction-and-preserved-allocation.md`。本例验证新诊断纹样的坐标方向和可编辑候选，不认证换装、蒙皮、模拟、真实织物裁剪或游戏引擎。

## 从消费者决定方向

Funcom《Armor and Clothing modelling Primer》的UV段要求平铺图案按需要方向布局，并按可见性分配像素；文中模块切口、图幅和材料约定属于Conan Exiles。原文：https://www.conanexiles.com/wp-content/wiki/2693791979.html （2026-11-14已读）。不能把其密度优先级或贴图尺寸当所有服装通则。

| 需要保持的内容 | UV决定 | 验收 |
|---|---|---|
| 已有文字、印花、刺绣或固定atlas | 保采样位置/方向/比例，或先明确迁移 | 原实际图案，同表面/相机/过滤对照；保留旧层不自动保外观 |
| 新方向纹样/织物纹理 | 先定义纹理轴与衣片物理方向，再选对应边/面域 | 实际PNG采样与3D局部图；一个锚边通过不证明整片经纬处处笔直 |
| 对称细条纹、普通无单向图案 | 区分“轴”与有向向量，180°可能等价 | 按实际图案对称性判断，不无端锁死所有转角 |
| 顺毛、单向印花、箭头或不对称细节 | 方向有正反，镜像/180°未必可放行 | 同时检查两侧、文字/毛向与法线/切线消费者 |
| 袖、领口、腰带、裙片等不同结构 | 分别确定沿长度、跨宽、周向等职责 | 不用全局世界Z或“所有岛朝上”代替解剖/衣片方向 |

U/V本身不是经纬：例如灰度随U变化的条纹，其线沿V。将领圈跨带宽边对齐V，会让这种条纹横跨带宽；换一种纹理定义，目标也要换。纹样方向、布料物理经纬、缝纫裁片和UV岛是关联决定，不是同义词。

## 优先保留有依据的原结构

本地T恤原UV有5岛：前身、后身、两袖、领圈。138条mesh开边形成领口、两袖口、下摆四环；不能当缺面补洞。实际内部UV切边144条，mesh seam却为0。直接按mesh seam重新展开会丢原切分；本轮使用`copy_uv`，未重展开或增加碎岛。

从原数组和3D图核面集后再命名：144切边分为前后身38、领身54、各袖身15、各袖纵缝10、领圈自身2。它们支持本例结构观察，不证明缝纫纸样就等于这5个UV岛，也不要求每件T恤采用相同数量。若确实需要重解，显式表达实际cuts/新接缝，并复核连续域，不只依赖seam标签。

领圈为54段周向、两列quad的带状表面，含宽段和窄折回。前中附近跨宽的相邻角点可作方向锚；本例公共`orient`只转整个领圈，保留其余岛形与实际切缝。领圈与身体不强求条纹跨缝同相位；只有具体设计要求连续印花/对花时才增加这项约束。

## 像素分配、留边与填图分开控制

1. **先定策略。** 默认“岛平均密度相差≤5%”不能证明不同衣片需要一样密。保留原作比例、统一新预算或重点分配都可以，须在动作前说明。本例选择保留源各岛比例，不由此推断原作者意图或预算最优。
2. **维护规则不是画质证明。** `settings`只设检查目标，不移动UV。本例先从复制基线记录5岛控制值，固定尺度pack时要求保持；之后的整体缩放目标由已声明的几何变换系数推算，而不是把新实测值填回来自证画质。
3. **一次pack失败保留为失败。** `rotate=false, scale=false`在本例出界；不能因此断言2K数学上放不下。若当前诊断用途允许降低绝对像素分配，可选对该排布整体等比fit；若绝对预算是硬要求，则不能用此方式通过，应比较其他有依据的排布/图幅方案。
4. **从实测边界计算一次fit。** 对图幅W/H、边距b及整体像素AABB跨度dx/dy，`s=min((W-2b)/dx,(H-2b)/dy)`；将整组选岛居中、等比缩放。各岛形状和方向保持，线分配乘s、面积乘s²、岛距也乘s，须重新测边距/最小岛距和UV舍入；变换前就核预测岛距不会低于需求。这个s只针对当前排布，不是全局最优packing证明。
5. **不以利用率掩盖取舍。** 本例实测AABB跨度2157.53223×2104.87325px，2K/16px图边算得s=0.9344008732；线分配下降6.5599%、面积下降12.6895%。最终图边16px、岛距约31.7695px。16px是本诊断选择，不是通用mip/压缩标准；仍须按实际目标过滤检查。

源OBJ未标单位。工作环境METRIC/scale=1和工具内部`px_per_m`字段不能证明实际米制；本例这些数值只作同一声明场景尺度下的分配保持控制，不宣传具有物理意义的px/m标准。正式资产预算需要先校准或获得可信单位依据。

对比畸变p95先核权重和取分位方法。本例三角计数等权的p95约1.22538，按世界三角面积累计95%的公共`area_p95`约1.13688；独立按相同面积权重复算才与公共值一致。两者不互相替代，也不能将UV面积当世界面积权重。整岛相似变换后的微小数值差须结合float写入与逐岛拟合残差判断，不包装成畸变改善。

## 输入与可用交付

本例原生OBJ导入保留1864个quad及所有引用角点/UV，仅省略源顶点池1个未被面引用的孤立条目并重编号；映射/原池有记录，源文件保持。公共`exchange.import STATIC`会冻结并三角化，保quad研究可选择经核参数的原生导入，不将其冒称逐索引无损或用来绕过UV几何拒绝。

公共流程为`copy_uv → 领圈orient → 事前分配/方向settings → pack`；首个pack出界保留，再显式改为整体fit策略，先计算预期控制值，再平移/等比缩放。源UVMap/render绑定、原材质、quad、岛面集保留；新纹样必须显式绑定新UV层，不能为展示而暗换原active_render。公共冷读、数值和真实图像分别检查。

可编辑输出、原作许可/内部使用边界、导入损失及所有失败均留在 `F:/Blender AI/runtime/audit/uv-d02-next-20261114-v001/`。本地用户资产未随技能分发；不得据本例授予公开分发许可。无rig仅支持本次静态方向诊断；抬臂/腋下形变、层间穿插、换装模板/图集、mip/LOD/目标引擎另验。整体等比变化不修局部畸变，也不代表织物外观整体升级。

## 接回原生工程与细分复审

原生`.blend`优先核真实面/角点对应，不能因OBJ工作网格看起来相同就按全顶点索引迁移。本例native1932点与工作1931点的差异为原孤点186；1864面/7456角点及1931个面引用点已完整对应。源码0.7.4的`transfer/EXPLICIT`可显式选`vertex_domain=FACE_REFERENCED`，仍验证全部面、角点、引用点双射和绕序；默认`ALL`仍拒绝此输入。孤点保留，不推断对应，不改几何。详细合同见[交换与交付](exchange-and-delivery.md)。

完整工程另存还要核原零用户ID是否落盘。原材质users0/fake=false会在普通另存后丢失；本例仅在新增辅助集合的ID属性建立真实材质引用，users0→1、fake与原内容保持，且可承受后续公共worker再次保存。新增持有者属于交付依赖，不可随意清理。不要批量改原fake-user或只看保存前RAM。四builtin字体users翻倍已由本次无编辑另存对照复现；只把这一计数单列，实际引用、名称/fake/path和23个相关GN节点仍逐值核对，不推广成其他ID可忽略差异。

迁移不继承源用途或默认均匀密度门。本例用上轮**事前已声明**的五衣片分配控制值重绑native geometry，未从新实测值反填目标，也未移动新UV。基础层数值和公共冷读通过，只证明本次迁移/维护范围。

原SUBSURF viewport1/render2、`PRESERVE_BOUNDARIES`保持；分别检查新层的真实VIEWPORT/RENDER图。当前原生实例两模式均在严格重叠检查失败，不能以基础层pass、有限/无退化、棋盘可见或累计面积很小改成最终表面通过。先保存实际求值数组/指纹、定位具体pair和共享几何端点，区分浮点微裂与非相邻折叠；不暗调epsilon、UV或modifier凑通过。RENDER捕获图也不认证原引擎置换或自适应细分。

本例完整3529/7299个正面积pair均共享几何点/边，非相邻0；最大端点差4/5 ULP（2K下0.0004883/0.0006104px），仅分析副本局部对齐后归零，严格fail仍保留。另有实际局部各向异性：RENDER tri31892/eval polygon15946的新/旧层最大比值约22.16946/22.16186。应先追溯原base面再决定UV或几何返修，不能把源已有畸变归为本次迁移错误，也不能让微裂解释覆盖真实局部质量问题。

本轮证据：`F:/Blender AI/runtime/audit/uv-garment-native-20261114-v001/REPORT.md`。原生可见目标无材质槽，packed旧图在隐藏源对象；它们不是可见目标的新UV消费者。新棋盘/条纹须显式命名UV层，使用保留原SUBSURF的诊断副本。无rig/动作，静态表面不能代签抬臂、合身、换装或生产验收。

## 细分局部返修：先追来源，再比较取舍

不能按求值面索引除以4/16猜父面。本例在临时副本给每个原面唯一FACE INT离散码，再核SUBSURF1/2后所有码合法、原面都有后代，以及几何/三角索引/旧新UV与未加见证的原图逐数组exact。由此将RENDER tri31892追到base996、VIEWPORT峰值追到1018；该分类见证不是位置或UV插值stencil，不推广到任意改拓扑modifier。

base996紧邻真实UV cut，其base各向异性约1.04，细分却升22.17：接缝UV角exact保留而3D点移动，求值UV角约173.55°、对应3D角约127.12°。低base畸变不能证明细分良好；也不能把源已有的问题归为新迁移错误。先看实际结构、原/新同处及同图层级身份，再选修法。

一次明确方法对照中，现有保界base ABF令RENDER峰值略恶化；原生`unwrap(use_subsurf_data=True)`在明确首SUBSURF/level2的隔离scratch提出C坐标，峰值22.17→12.21，但base/求值的面积加权p95均略升。只改变UV Smooth全部平滑的控制则把峰值移到别处，且几何不再exact，未采用。不要反复调保界迭代数，也不要只看旧热点或一个最大值；比较全域分布、最大值位置、原预算与真实图像。

C仅有4个UV点、16角点改变，固定/未选UV、cuts及原几何/modifier保持。提议可由现有公共`copy_uv→settings→4组LOOPS translate`精确落实新层`UVW_ClothPatchC`，没有新增或宣称通用自动细分感知求解入口。别把隔离脚本输出直接写进目标后冒充公共开发通过。新候选两模式完整分类仍只有几何相邻微小交集、非相邻0，raw strict fail保留；生产用途未批准。

同机位真实PNG近景可加明确标注的重复频率作局部诊断，不称更高分辨率贴图；普通频率图变化弱时如实报告。新图部分格线展开，但尖折/跨缝相位差仍在，不能把44.9%的峰值下降宣传成整体画质提升。源、原候选保留；新诊断工程独立冷开复渲逐像素一致。证据与取舍见 `F:/Blender AI/runtime/audit/uv-cloth-stretch-repair-20261114-v001/REPORT.md`；Wiki正文仍为本条开头入口，当前领域生产边界不变。

## 临时冻结、真实约束与图幅边界

局部solver的chart边界临时pin不等于用户硬pin。要释放它，先由实际record和持久UV核fixed/pin/lock，再区分patch外圈、含未选角点的连续别名与完全内部的UV切缝两侧。本例22面内free16→36，新增20角点为12个完整别名群；7420 held保持，真实cuts/seams和两侧分离保持。此资格只证明可以研究该自由度，不预授质量通过。跨缝相位仅在实际对花/固定印花消费者要求时设为约束。

一次E实验减轻旧热点，却将RENDER全域最大值由C的12.21414推至邻面base1002的26.53825；loop1463从x=16.0000019px移到−3.0990744px，违反既定16px图边。预算、方向与几何保护通过不能抵消失败；不保存、不clip、不反复重解。保留C的取舍候选及其strict fail，不将E的局部改善宣传成新成果。

对提议方向先核可行步长：若`x(alpha)=x0+alpha*d`且d<0，图边b要求`alpha≤(x0−b)/(−d)`；其它上下边同理。已贴边且朝外的点可能把全方向步长压到近零。只防翻转的line search不自动维护图边、岛距或预算；逐分量裁剪也会改变原方向，须作为新方法另验，不能当原求解已通过。本例的精确上界与停止证据见 `F:/Blender AI/runtime/audit/uv-cloth-seam-freedom-20261114-v001/REPORT.md`。这只否定C→E此方向，不证明所有UV修复无解；后续须有纳入图幅/质量目标的新方法或实际消费者需要，不能继续同一路线试参。
