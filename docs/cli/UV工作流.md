## 入口与结果

`blenderctl.ps1 uv describe`返回所调用入口的合同、实现身份与未支持项。0.8系列operation为generate、inspect、validate、adopt、restore、edit、recipe、copy_uv、settings、seams、lightmap、transfer；`uv run --params <UTF-8 JSON>`执行写操作，`uv inspect --params <UTF-8 JSON>`只读检查。公共request命令名为`uv.run / uv.inspect`。全局`--jobs-dir / --compact / --async`置于子命令前；用独立审计作业目录。

`generate.methods=["MINIMUM_STRETCH"]`采用原生SLIM，可设`slim_iterations=1..100`（默认10）与`slim_no_flip=true`；局部`edit.action`用`kind="unwrap", method="MINIMUM_STRETCH", iterations, no_flip`。不隐式加接缝。需要角度/锐边建议时用只读`inspect.seam_suggestions`，实际标缝用显式`seams`操作。

`lightmap`通过原生`lightmap_pack`建立非`active_render`辅助层；0.8.1要求完整`metrics.status="pass"`后才报告`lightmap_ready`，fail/unknown均拒绝并恢复目标层及pin/活动/渲染状态。该状态不认证目标引擎的烘焙、mip或光照泄漏。`overwrite=true`是显式替换目标层：非渲染活动层仍可能被普通显式UV Map材质采样，覆盖前核对消费者；保留现有UDIM/托管层/渲染层拒绝规则。

params必须给file（绝对blend路径）、expected_sha256、resources（已核实资源描述列表）及manifest；可提供implementation_sha256固定实现。manifest明确version=1.0、Scene/ViewLayer和唯一对象名列表；写操作指定candidate。未知字段拒绝，不支持的约束不静默忽略。当前字段以describe为准。

`constraints`是新候选输入：generate、copy_uv或transfer在省略时补为空对象。已有候选的validate/edit/adopt/restore省略该字段时沿用候选记录；若显式提供，规范化后的值必须与候选原manifest.constraints相同，否则CONFLICT，包括显式空对象也不能覆盖原有非空约束。此比较针对创建输入，不是把当前受管pins/locked_faces重新写回原manifest。修改现有固定点请用pin/lock/sync_pins，当前接缝计划和切开/连续硬约束用seams；不能借普通请求携带新constraints静默覆盖。recipe/settings/seams各有严格独立字段，不能带constraints。

生成只写新候选层和新作业候选文件；共享Mesh直接修改拒绝。采用改变编辑层与接缝计划，保留原UV、材质和渲染绑定；恢复前检查手改。原生UV或pin改变须重新validate，违规或不完整检查不能视为通过。需要让贴图改用新UV时单独走材质/烘焙协作。

公共作业校验源、资源与实现身份，严格保护非目标，另进程独立重开。ok=true表示操作完成，不自动批准候选质量；仍须读metrics、完整性、视觉和用途接受记录。超预算unknown不算无重叠。输入为SAVED_DISK_V1，不检测GUI未保存编辑。

## M5 求值表面：显式帧的只读检查

`uv inspect` 的 manifest 可增加 `surface`。它从已保存工程只读检查形态键、骨骼和受支持修改器之后的网格，不写UV，不应用修改器，不保存源文件。基础网格候选检查与求值表面检查分别报告，原有用途配方和视觉批准不会自动继承。当前生产已支持 local single-user shape keys 的写路径：safe scratch 只清理临时 Mesh Key，源 shape/weights/target、实际引用 rig/action/attrs 受完整性保护；共享 Mesh、共享 shape-key datablock、linked/override 目标仍拒绝，不能删 Key 或改无 Key 副本绕过。可写 shape 不等于所有 rig 控制类型、任意约束或任意驱动器结构都受支持；未表示/未认证结构明确拒绝。

以下是本批受控输入的manifest示例；外层params仍必须提供实际file、expected_sha256和resources。示例没有用途policy，数值pass只表示完整硬检查通过，不能解释为拉伸已满足生产用途。

```json
{
  "version": "1.0", "operation": "inspect",
  "scene": "Surface_Fixture", "view_layer": "Main", "objects": ["DeformingPatch"],
  "width": 2048, "height": 2048, "pair_budget": 2000000,
  "surface": {
    "layers": {"DeformingPatch": "UVMap"},
    "frames": [1, 10], "modes": ["VIEWPORT", "RENDER"],
    "triangle_limit": 10000, "usage": "EXCLUSIVE"
  }
}
```

frames为1–8个不同整数帧，modes显式选择VIEWPORT/RENDER，可任意排列；layers精确覆盖目标。triangle_limit为1–2000000，按每帧每模式的全部目标合计；它是在Blender完成求值后限制测量规模，不是求值前内存硬上限。全量测量不减面，超限返回unknown/triangle_limit；pair_budget仍为每个检查阶段的候选对预算，预算不足同样不能作为通过。frames是离散样本，不能证明连续动画无问题。

VIEWPORT使用实际视口求值图，隐藏目标拒绝。RENDER由临时RenderEngine回调获取真实RENDER模式求值图，使用render级修改器设置，报告明确`render_capture_engine`与`configured_renderer_equivalence=not_verified`。**它不认证原Cycles/Eevee的着色器置换、自适应引擎细分、材质、像素或过滤结果。** 本批实际Cycles棋盘用于观察形变；用depsgraph_update_post捕获Cycles图的尝试未得到RENDER回调，不能以这两张图证明两个引擎几何完全等价。

默认使用显式`EXCLUSIVE`，不迁入基础岛的声明。0.8.3可显式选择`CANDIDATE_EXACT`并在surface内提供`candidate`：目标顺序、Scene/ViewLayer、Mesh身份、候选层、尺寸/单位、geometry、UV+pins及settings必须匹配；settings须为非空reuse的EXCLUSIVE。每个真实样本还须有限且精确匹配base的局部/世界位置、有序edge/loop/polygon/triangles、逐loop UV与数值岛归属，才能把reuse交给测量器。任何变化均unknown且reuse_used=false，不回退为通过；active BEVEL改变拓扑就不能使用这条门。最终静态副本需在外部明确建立新身份，surface从不apply或保存。该门不继承密度配置或用途批准。可选`surface.policy`仍仅允许ISLAND_AREA_REFERENCE，reference是调用方声明。最终交付应实际检查VIEWPORT与RENDER，离散样本不代签动画或目标渲染器。

普通ARMATURE、SUBSURF、MIRROR、SOLIDIFY、BEVEL、TRIANGULATE、平滑/法线、SIMPLE_DEFORM、CAST、LATTICE、SHRINKWRAP、MASK进入已定义求值路径；是否合格仍由实际指标决定。任意GN、模拟、烘焙缓存、实例扩展未放行；只允许递归核对节点能力的Smooth by Angle着色图，不凭节点组名字信任。RENDER隐藏或求值图缺目标、缺UV层、未知修改器明确unknown/unsupported；视图层排除导致找不到目标时按NOT_FOUND拒绝，不静默跳过。注意：普通 modifier 的配置/设置保护通过 ≠ 最终求值认证；最终表面仍必须由保存盘 `surface` 另行采样。

完整报告逐帧记录形态键状态、实际三角数、世界几何/UV指纹、指标和用途检查。完成与异常路径均恢复帧/子帧、窗口上下文、相机、引擎、分辨率及相关渲染开关；报告核对controls_before/after。compact保留求值模式、三角数、完整性和未验边界。批量只允许全部样本完整pass进入后续审阅/复用，并交叉核对目标/UV层、模式、三角数、预算、完整性、用途和恢复证明。0.8.4支持EXCLUSIVE或显式CANDIDATE_EXACT；后者还要求reuse_used=true、候选一致、有序目标一致、finite_numeric_values_no_tolerance比较、每对象有效且相等的base/evaluated SHA、match=true/first_mismatch=null，以及非空、成员合法且跨样本一致的reuse_groups。缺证据、fail或unknown不能作为通过。GUI实时多帧检查未支持，应先保存明确工作快照再通过CLI检查。

## M5：完整性、diagnostics、面板与作业

生产自 0.7.0 起 的完整性检查以 local single-user 网格为边界：保留 shape keys、顶点组/权重、受完整性表示的 modifier 设置与引用、目标及实际引用 rig 的动画/rest-pose 和 non-UV attributes；基础网格求解只清理临时复制的 Keys。共享 Mesh、共享 shape-key datablock、linked/override 目标、任意未表示的形变结构仍拒绝。普通 modifier 的配置保护通过不等于最终求值认证；最终表面另按 `surface` 检查。可做 shape 写入不等于所有 rig 控制类型、任意约束或任意驱动器结构都受支持；未表示/未认证结构明确拒绝。

`manifest.diagnostics` 是 inspect-only：`{"max_examples": 1000}`（1–10000，默认 1000）。返回每对象全量 vertices/edges/faces/triangles 计数、按对象/面/边/点/loop 的有界定位示例、普通 geometry 身份、诊断几何 SHA、`status`、`handoff`、`mutation="none"`。`examples` 可截断，`counts` 全量；不修复、不认证任意自相交或最终求值表面。面板“定位网格问题 / 建模交接”写入 Text block `UV-Geometry-Handoff.json`。

面板后台作业监控只读显式选择的 `uv.run`/`uv.inspect` 作业 `status.json`（批量用 CLI `job wait/status`）；persistent timer 在切换文件后继续显示 job id/state/阶段/耗时/心跳，OSError 只做有界重试。状态/进度不是 UV 质量或当前工作区通过。当前姿态棋盘是 frozen VIEWPORT 求值快照；`surface_report`只读不超过128MiB的保存盘`uv-report.json`，要求当前文件SHA匹配、样本完整、controls restored、用途一致；CANDIDATE_EXACT通过样本须有候选与有限精确身份。读取FINISHED不代表表面通过，fail/unknown原样显示；dirty工作区不算通过。报告只存在当前进程内，保存后须重新检查，独立重开后重新加载。配置渲染器置换/自适应细分仍未认证。

0.7.3将“停止查看”固定在进度信息之前，避免阶段、耗时或心跳行变化推动操作位置；停止查看后主动刷新所有3D视图。该动作只清除本地监视和timer，不发送后台取消请求。真实运行期间的界面接续证据与限制见`work/audit/<batch>/`；独立GUI直接用公开操作符接入真实status路径与文件选择器交互分别记录。

## M3a：源UV到新目标候选的受保护迁移

`operation=transfer`在同一明确Scene/ViewLayer内，从显式源对象UV迁移到目标的新候选层。顶层objects只列目标，所有源名与整个目标名单必须不相交；一个请求可有多个目标、不同源或不同模式。需给未使用的candidate和正有限`transfer_unit_scale`，绑定当前scene.unit_settings.scale_length；width/height按目标图幅，pair_budget为整份请求共享预算。transfer创建候选时也支持目标constraints、边距和可选density_px_m；显式methods、selection/action、recipe/settings等不属于迁移请求，不能借此继承或改写其他操作。

`transfer`必须恰好覆盖目标名，逐目标字段如下；身份值从inspect的transfer_identity或已确认的只读捕获取得，不能填写示例假SHA。

| 字段 | 精确结构与含义 |
|---|---|
| source_object / source_uv | 同视图层的源mesh名与明确UV层名；不依赖执行时活动对象猜源 |
| source_binding | {geometry, mesh, uv_hash}；源基础几何/世界变换、mesh身份、该层UV及pin指纹 |
| target_binding | {geometry, mesh, protection, active_uv}；目标几何/mesh、原UV/pin/材质/seam/render保护hash及旧活动UV名（可为null） |
| mode | INDEXED、EXPLICIT或PROJECTED；各行只接受本模式字段 |

源或目标的绑定、单位发生变化时拒绝旧请求，不重新采样并悄悄重绑。共享目标Mesh、库链接/不支持上下文、新层同名或槽位不足等明确拒绝。已用或未解析UDIM来源/目标旧层保持保护；这不是把UDIM变为普通UV的入口。同一对象内复制请使用copy_uv。

### 三种对应方式

| mode | 额外字段 | 实际保证与限制 |
|---|---|---|
| INDEXED | 无 | 顶点/面/loop数量及每面顶点序列、loop序列必须相同，才使用target-loop→同索引source-loop的完整映射；相同面数或看起来相近不够。几何位置不必重合，目标拉伸另验。 |
| EXPLICIT | corner_map、winding；可选vertex_domain | corner_map是整数列表，第i项为目标loop i对应的源loop编号，不是成对列表；完整且唯一。winding=PRESERVE或REVERSE。省略vertex_domain或ALL时验证完整corner/face/全部vertex双射；显式FACE_REFERENCED仅将vertex双射域定为各自面角点引用的顶点，仍完整验证corner/face、引用顶点双射及绕序，不按最近点猜测。 |
| PROJECTED | regions、max_distance_m、normal_degrees、uv_tolerance_px | regions为[{source_faces:[...],target_faces:[...]}]显式面域；每个目标面恰好被一域覆盖，不能重叠或遗漏。距离为世界米且≥0，法线夹角0–30°，UV容差>0且≤1像素。面板使用全源面→每目标全部面；分域通过完整JSON请求。 |

PROJECTED只支持显式域、近共面单层、完整裁剪投影覆盖及目标三角可表达的分片UV。它逐目标三角裁剪源片，检查源片正面积重叠、缺覆盖、距离、前向法线和面内UV一致性；不能仅以角点命中或面积和相等证明迁移成功。薄层多重覆盖会拒绝，须用可信显式域排除歧义；不是任意曲面最近点、薄层自动识别或任意重拓扑迁移。源UV接缝穿过一个无法表达该跳变的目标三角、非仿射变化、共享目标loop要求不一致时拒绝，不自动分面或改几何。目标已有边界与源seam对齐的有据情况可通过。

世界坐标从Blender已存局部坐标/矩阵用float64计算再乘单位，避免额外float32世界乘法舍入；这不恢复输入本来已经丢失的精度。最终写入仍是float32，PROJECTED会以实际最终corner值在每个保留裁剪片顶点重新插值，按像素度量`max(|ΔU|×W, |ΔV|×H)`核验源UV误差。数值尺度判定使用公开NUMERIC_POLICY；若`max(1e-15 m², 1e-11×目标三角面积)/目标三角面积 > 1e-4`，明确UNSUPPORTED，不能用绝对epsilon掩盖相对大缺口。预算/取消在未证明覆盖时停止，不冒充成功；pair_budget不代表高密性能或硬时间保证。距离/夹角/像素容差是测量约束，不是外观批准。

### EXPLICIT的FACE_REFERENCED选项（0.7.4）

只在某目标的`transfer[target]`行增加`"vertex_domain":"FACE_REFERENCED"`，不是顶层字段。源/目标在面角点引用域内仍须完整一一对应；未参与面的顶点没有UV角点，迁移不猜测它们的对应，也不删除、移动或清理它们。INDEXED/PROJECTED不接受此字段。

报告明确给`vertex_domain`、两侧总点/引用点/未引用点数量、排除索引（有界列表附truncated）与`mapped_vertex_count`。原`checks.vertex_bijection`仍表示全Mesh；有未映射孤点时保持false，同时`face_referenced_vertex_bijection=true`、`full_vertex_bijection_required=false`，不能把较小域的通过称为全顶点对应。全部几何/非目标保护、有限值/退化准入、完整角点/面映射和绕序、单位/资源绑定保持原规则。

### 事务、源保护与GUI接续

所有目标先只读完成对应和数组检查，再统一创建`UVW_<candidate>`及Scene记录；源始终只读，目标原UV、旧活动层、render和材质绑定保留。目标原生pin及请求硬约束继续有效，不能用源值覆盖不同目标锚；硬约束或提交保护失败删除本次新层并恢复state，普通质量fail则保留明确失败候选、不能adopt。源pin/用途配方/视觉接受不会复制为目标批准，目标需按自己的用途重新绑定并检查；BASE_MESH迁移不等于修改器最终表面或姿态通过。

公共保存重开除目标与非目标保护外，单独核对去重源集合的全部UV/pin/seam/render及活动UV。只改源pin、活动层或render层的保存副本反例会在源专门检查处拒绝；不能只凭目标UV相同宣称源数据安全。

面板独立“从已有UV迁移到新候选”区只在Object Mode记录/执行，不偷偷退出Edit：先活动源与UV→记录源身份，再选择目标（排除源）→生成草稿，核对显示的源层/目标/模式/范围后执行。生成草稿前确认源记录未变；执行只使用已存manifest，不从后来选择或控件重建，core成功才切新candidate，失败保持旧candidate。JSON导入/导出只记录完整请求，不执行；导入保留原源/目标绑定，EXPLICIT或多源/分域请求不自动重绑，导出不覆盖已有文件。成功后可按原候选检查/采用/原生编辑流程接续；Undo/Redo的数据和记录仍以Object事务一起恢复。

## M3b：格式交换与贴图迁移协作

UV、交换和材质/烘焙分别验收，沿用公共exchange.export、texture.bake、material.run、render.run，不在UV插件里复制完整烘焙器。交换回执中的几何重开pass不自动证明多UV/材质正确；按实际格式读取每面角点、层映射及有效材质。

| 当前实测格式 | UV结果 | 已知损失与边界 |
|---|---|---|
| GLB静态 | 两UV层完整保留，TEXCOORD_0/1；V翻转，实测误差≤2.98e-8 | 重导入层名变UVMap/UVMap.001，active/render选第一层；原Blender层名与编辑状态不保真；materials=NONE无材质 |
| FBX静态 | 所测两层名称、坐标保持，角点误差0 | 不据此保证shader、任意modifier/骨骼/动画等价 |
| OBJ静态 | 只保留活动的一层 | 明确不支持多UV；不能把导出成功解释为全部UV保留 |

本批对4tri控制件及148480tri青花求值静态表面实际导出并独立读取；删除GLB第二UV和修改单U负例能被检查发现。层名、排序、active_render及贴图采样的texCoord必须显式映射，不能仅看“有两个UV”。证据在work/audit/<batch>/。

STATIC交换现按evaluated Object.material_slots物化实际有效材质，再对实际导出对象检查GLTF_PBR支持范围。不能仅读取Mesh.materials，因为OBJECT链接可覆盖它；写永久mesh必须取material.original，不能挂depsgraph临时材质。红/蓝OBJECT和白DATA公共回归保留正确颜色与两层UV；复杂青花显式UV/normal/coat超现有窄GLTF_PBR时明确UNSUPPORTED，不再静默导出白材质。此修复没有扩大PBR子集。

旧图迁移前须明确旧shader所用UV，尤其隐式Vector消费者；切换烘焙目标active_render不应改变旧图取样。新UV保留旧层，新材质另建并保留旧材质/依赖。要提取原Base Color，专用工作副本中显式捕获颜色信号；完整Principled的DIFFUSE_COLOR可能含specular/coat能量衰减，不等于Base Color。NORMAL单独烘焙，记录目标UV/TBN、OpenGL +Y和已烘入强度，不能当普通彩色图复制。

线性颜色转sRGB必须实际编码RGB字节，alpha不套该转换。保留原PNG16的线性精度，OETF后仅最终PNG8一次量化；Pillow的RGBA16转RGBA8会提前丢精度。Blender5.2.1的byte image.pixels读写与float buffer语义不同；设置sRGB标签、写线性pixels再save并回读相同，不证明完成编码。用实际PNG字节显式逆传递函数核对线性信号，再在同相机/光照下比较源、迁移版与错误直接改绑对照。小数值差、FINISHED或比错误对照好都不单独构成外观通过。

材质工作有意更改消费者或材质槽后，旧UV候选的protection可能失效，这是正确的保护拒绝。不得篡改旧记录hash；保留原记录，以当前明确来源层用公共copy_uv新建候选，重新建立当前材质上下文的保护基线并独立检查。copy_uv保持旧层和材质正在使用的UV消费者，不自动将贴图切到新编辑层，也不继承旧用途批准。继续改UV而要同步外观时，仍需新的烘焙/材质迁移。

本批青花初版及第二版外观均未通过父审；v004颜色编码修复经实际PNG字节和三视角/口沿观察通过受限复核，但实际RENDER细分求值存在13850对真实正面积相交，仍隔离为fail，不能因亚像素而放宽。成功对照及最终支持状态由本批M3-ACCEPTANCE.md与REPORT.md记录。UV专项不承担修几何，最终表面与用途数值/视觉独立签署；多模型、姿态与高密扩大验证仍按M4/M5执行。

## 复制现有UV与当前接缝管理

`operation=copy_uv`要求`source_layers`恰好覆盖objects，例如`{"Product":"UVMap"}`，以及一个未使用的新candidate编号；复制到`UVW_<candidate>`，不运行展开求解、不覆盖既有层。源坐标和pin、原活动/渲染层及材质消费者保留；source_uv约束若与指定源层冲突则拒绝。复制结果仍完整检查，可作为fail/unknown候选修正。共享Mesh、层名冲突、层数不足或既有/未解析UDIM来源均拒绝。面板“复制各对象当前UV为新候选”使用各对象当前活动UV和新候选图幅，自动分配新编号。

`operation=seams`只接受身份六字段（version/operation/scene/view_layer/objects/candidate）和`seam_action`，后者为`{"mode":"MARK","edges":{"Product":[2,7]}}`。MARK/CLEAR只改候选seam计划；REQUIRE_CUT/REQUIRE_JOIN分别设置must_cut/must_not_cut、去掉相反规则，并相应标记/清除计划；FREE解除所选边两类硬约束但保留计划。它们不自动切分或焊接UV，暴露待修布局时保存fail，不能adopt。已adopt的候选同步显示mesh seam，未adopt时保持mesh seam。原生手改后须先validate；面板选择当前候选边后Tab回Object Mode执行，数据与state共用一次UNDO事务。

## 局部编辑

`manifest.operation=edit`修改指定已有候选层，增加revision；公共入口仍另存新作业文件，不覆盖输入。`selection`按对象给出`domain`和`indices`：ISLANDS的索引是原网格面种子，并扩展为候选UV完整岛；FACES为精确面索引；LOOPS为精确角点索引。不能将排序后的岛编号作为面种子。可选`selection_binding`绑定candidate及所选对象的geometry/uv_hash；过期则拒绝，原生手改须先validate。

旋转/缩放/镜像默认枢轴为所选像素坐标包围盒中心。未选UV逐值保持，固定点或硬接缝约束冲突时整次回滚。普通质量失败的编辑候选允许保存供修正，`ok=true`与`candidate_edited`不代表质量通过；compact中的record.metrics.status和last_action明确呈现此区别。沿用候选原用途配方，不因编辑自动放宽密度或边距标准。

面板先采用候选为活动编辑层，在Edit Mode中记录当前选择；成功捕获会回到Object Mode，在此执行并检查，完成后用Tab或“继续原生编辑”接续。执行时再次核对活动候选层。UV点捕获目前要求关闭UV同步选择，且仅包含选中、未隐藏面的UV点；面/岛范围可保留同步。捕获绑定到当时状态，编辑或原生修改后重新记录。新捕获失败时旧选择失效，防止误编辑先前区域。

面板宽度/高度只用于生成或复制新候选，默认2048×2048，可设置长方形图幅。候选下方显示其实际保存图幅；后来修改新建宽高不会改变已有候选的测量或求解配方。像素边距不能超过可用图幅，仍按核心契约拒绝无效设置。

面板“新建候选约束（活动对象）”只记录下次generate的约束草稿，不修改当前候选：Edit Mode选边或面 → Tab回Object Mode → 记录必须切开、禁止切开或固定面；隐藏元素排除。清除同样只清该对象的生成草稿。当前候选的固定点和锁面由上方pin/lock/sync_pins单独管理，不能把下方新建约束误认为已同步到当前候选。候选操作与局部编辑也要求Object Mode，避免Blender的EditMesh撤销只恢复网格而漏掉Scene里的约束、检查记录。原生全局撤销须处于开启状态；本批没有改用户偏好，未验证关闭全局撤销的行为。

局部放松与重展只调整自由内部角点，保持选区周界、已有UV岛切口、人工固定点及其连续角点别名。无自由内部点时明确返回`not_run_no_free_interior`；不改变整岛边界形状。每对象在独立工作网格按世界几何求解，以配方W/H计算像素比例；候选原材质、活动层及原生接缝旗标均保持。原生求解结果还须通过独立检查，改善不是保证。

原生手工pin与候选记录中的固定约束不一致时，即使validate过，普通局部编辑仍拒绝。validate只更新检查与当前UV/pin指纹，不自动吸收或清除人工pin；可继续用显式sync_pins导入所选范围。当前seam硬规则的显式变更已由独立seams操作管理，不能误认为validate自动理解并同步全部制作意图。

### 原生固定点同步与锚点

原生修改pin或固定点坐标后，先回Object Mode执行validate，再重新记录当前选区，最后执行`action={"kind":"sync_pins"}`。仍沿用候选UV/pin指纹与可选selection_binding检查，不能直接跳过重验。同步范围可用LOOPS、FACES或ISLANDS；任何选区外的原生pin差异（包括未选对象）均CONFLICT拒绝，不会顺便导入。

仅所选且不属于locked_faces的角点可按当前原生pin状态增删受管pins；所选仍被pin的非锁点显式采用当前位置作为新fixed锚点，并在details.reanchored_pins列出已有锚的改变。未选仍有效的fixed锚逐值保留。锁面所有角点须仍原生pinned且坐标等于旧锚；不能解掉锁面pin，也不能借同步重锚锁面。同步保留锁与普通pin的角色，不把锁生成的旗标额外转成普通pin，避免以后unlock仍意外固定。

sync_pins不移动任何UV，也不改输入原生pin旗标；只更新约束记录、检查与revision。普通pin/lock也保留所有仍有效的旧fixed值，仅新增fixed键记录当前位置，不能借其他区域pin/lock静默重锚手改点。需要改已有非锁锚时用显式选区同步，或明确解除相应约束。0.2.3不追溯重建旧版本已经重锚并保存的历史值；没有可靠旧锚时须由用户核对原始记录或备份，不能猜测恢复。

### 指定面侧切分

`split`仅接受FACES显式移动区域；delta_px按候选W/H分别换算并平移该区域全部角点。至少存在一条跨选/未选的原连续双面mesh边，并且这些连续边界必须真正新增数值UV切口。所选区域内部连续性、全部旧切口和未选UV逐值保持；切口集合须恰为“旧切口 ∪ 此次连续选区边界”。整岛无可切连续边界、零位移、float32舍入后未切开、位移会焊回旧切口，或跨选区非双面边均拒绝。此动作不改几何拓扑，不提供零距离拓扑切分或任意单边自动割缝。

delta_px定义位移方向和距离，不保证边界最短间距等于位移长度。pin/lock/must_not_cut冲突走统一拒绝与回滚；数值切分后碰撞、越界、间距、密度或用途quality fail则保留已编辑fail候选供修正，不能adopt。未adopt时mesh seam不改；已adopt时依候选seam计划显示新增切口。

所有edit动作的seam计划现在只在旧计划上并入“本动作后的数值切口减去动作前数值切口”，不会把此前已有但有意不标记的数值切口全部补回mesh seam。stitch的CLEAR_JOINED仍额外仅清除本次明确缝合且结果连续的边；KEEP和既有计划的其余部分保持。

### 受检成对缝合

`stitch`只移动显式角点，不移动整个岛，不使用中点吸附。`action.pairs`的对象集合必须与selection一致，每个选中移动角点恰好出现一次；静态角点不得同时列为移动角点。配对端点须对应同一mesh顶点，移动侧包含该UV顶点的全部连续角点别名，且这些别名只能指向同一静态UV位置。配对必须覆盖完整双面mesh边的两个端点；任意孤立点配对、已经连续或目标不一致均拒绝。每对按候选图幅W/H计算像素距离，超过limit_px拒绝；移动侧pin/lock仍受统一固定点检查，不能借缝合移动固定点。

`KEEP`保留既有接缝计划，即使数值UV已连续也不自动清mesh seam。`CLEAR_JOINED`只从候选计划清除此批明确配对且结果已连续的边；硬性must_cut等约束不能被绕过。候选已adopt时才同步其mesh seam显示；未adopt时不改生产mesh seam。原始层与静态侧坐标保持，失败仍按统一事务处理。

面板中先采用候选，在Edit Mode选择与静态活动面相邻的双面接缝边，点击“记录接缝边两侧（活动面固定）”；捕获自动补齐移动侧角点别名并回到Object Mode。设置移动像素上限与接缝标记策略后“执行并检查”。静态侧由活动面确定，不由岛排序或不明确的选择顺序推断。

### 受检整岛排布

`pack`按面种子扩展完整数值UV岛，跨对象在一次隔离scratch中联合调用原生pack，再交统一事务提交和完整候选检查。选中岛任一managed pin或锁定面使该整岛固定；有这种选中固定岛时必须`scale=false`，`scale=true`写前UNSUPPORTED拒绝。未选UV和固定整岛最终从输入副本逐值保留；原生工作空间保护漂移超出允许舍入或数字UV切口改变时拒绝。无可移动岛时明确no-op。

排布按像素比例工作，预留图边后采用短边内接方形区域，长方图长边尚未充分利用；有固定岛时不整体居中或事后fit。原生间距只是求解提示，不保证可行布局。未选岛不保证作为原生障碍：实证中未选逐值不动仍可与选中结果产生正面积重叠。最终对整个候选检查三角形、碰撞、真实像素gap、边界、密度与用途；FINISHED、candidate_edited或文件写出均不代表排布通过。普通quality fail保留明确fail候选供修正，不能自动采用。

0.7.5按实际Blender5.2行为区分全自由与选中锁岛：全自由时FRACTION双边累计，单边传入`(gap_px+1)/(2*span)`；有选中固定岛时保守传入`(gap_px+1)/span`。保留总计1px安全量，0请求也不承诺实际零距。gap/border字段是最低值，混合锁/自由可超间距；edit原生外边padding叠加请求border，生成后fit另查实测，二者不保证完全相同。未选pin不是参与的选中锁岛；partial全局碰撞仍由完整检查拒绝。探针、7条件pack回归、声明复用别名精确保留、D06同输入生成/编辑与求值证据在`work/audit/<batch>/`。同cuts生成覆盖38.30%→54.54%只属本例，不能代签细小侧面采样、全车或引擎质量。

声明复用组参与pack时必须选中该组全部成员，或整组不选；任一成员固定会固定其代表岛。原生只排代表布局，再恢复组内对应坐标，保持声明复用足迹和数字切口。TILED不使用图集pack，应使用密度、方向和明确重复布局。

### 有向边与显式堆叠

orient选区必须是单个完整数值UV岛，edge_loops为其中同一面相邻角点；按W/H计算方向并转向angle_degrees，保持数字切口，统一检查pin/lock和已绑定方向规则。面板在活动面恰好选择一条边，按面内loop绕序记录起点→终点；角度有方向，反向边不是同一朝向。捕获同时绑定geometry、UV/pin指纹，原生编辑后重新记录。

stack不猜坐标最近点：每个移动完整岛的全部角点须与参考完整岛一一双射，面也一一对应、顶点对应一致；mirrored=false保持面角点绕序，true使用反序。参考岛不能同时被选为移动岛。同对象多个岛和跨对象岛均可配对，不同或不一致拓扑明确拒绝。成功后创建group_id对应的完整成员声明；已有同名组拒绝。unstack按显式offset_px分离选中岛并移除其旧声明成员；剩余不足两成员的组删除，位移仍非最小gap保证。

面板先独立记录参考活动面所在完整岛，再选择移动岛并“生成配对草稿”；按面索引排序、面内loop顺序显示全部角点对，镜像反序。此时不移动UV，用户核对后点击执行才stack；切换镜像设置或参考UV改变使旧草稿失效。该确定配对方法不承诺自动识别任意重拓扑对应。

## 布局settings：使用方式、重点密度与方向

`operation=settings`只接受身份六字段和完整`settings`。settings字段为version=1.0、binding、mode、reference、reuse_groups、density、directions；binding与recipe同样精确绑定BASE_MESH、世界变换、单位和图幅。无既有settings时从policies.defaults(该绑定)开始；面板每个按钮只更新对应字段，保留其他规则。该操作改变规则、重算检查，不自动移动UV；文件导入也不自动重新绑定陌生模型。

| 字段 | 内容与边界 |
|---|---|
| mode / reference | EXCLUSIVE或TILED，以及明确用途说明；不能从UV超出0–1或整数格子推断模式 |
| reuse_groups | [{id,members:[{object,faces}]}]；每成员恰好一个完整数值岛、同组完整UV面足迹相同；一个岛只能属于一组 |
| density | {default_px_m:null或正数, regions:[{object,faces,target_px_m}], relative_tolerance:0–1}；regions是完整岛且不可重叠 |
| directions | [{object,loops:[起点,终点],angle_degrees,tolerance_degrees}]；同一面真实相邻角点，容差0≤值<90° |

EXCLUSIVE仍记录全部raw正面积相交；不同完整岛在同一显式reuse组内的相交记declared，其余为undeclared。岛内折叠始终不因声明而放行，声明组足迹改变或成员不再是完整岛须修正/解除声明。`overlap.positive_pairs`是原始总数，declared_positive_pairs与undeclared_positive_pairs分别列出声明和意外相交；raw非零不等于全部违规，declared非零也不代表无raw重叠。只有EXCLUSIVE且无复用组才满足这里的独占烘焙语义。

TILED是显式单图重复用途，允许跨岛重复和图幅外重复；同岛折叠、无效几何/UV仍失败。图边和岛间间距在用途检查中为not_applicable，不把原始signed boundary诊断当作边距达标；gap.reason=tiled_usage。一个声明布局组也可使gap为no_distinct_layout_units的不适用情形。TILED不等于Blender图像source=TILED/UDIM，也不会改材质节点、图像extension或渲染绑定；inspect中消费者REPEAT证据与用户声明分别保留。

指定密度逐岛取优先级“区域目标 → 默认目标 → 原manifest density_px_m”；任何岛缺目标时configured.complete=false、结果unknown，不只统计有目标的子集。原始岛平均密度与全岛相对均匀性仍独立保留，重点区域可故意不同密度，不能把raw偏差藏掉。面板“记录重点完整岛选择”后设置/清除所选岛目标，只改规则；需要实际缩放另用density动作。方向规则也是数值检查，偏离有向目标使约束fail；orient负责实际转向，不能靠放宽规则冒充布局已转正。

面板布局settings文件与通用用途recipe文件分开展示。settings包含具体面成员、角点方向、复用组及严格绑定；可移植的是经过重审的规则意图，不是旧面/角点身份。导出不覆盖已有文件，导入保留原binding，不因导入自动绑定到陌生对象；通用policy与此类具体布局身份不可混用。

## 用途配方：绑定、检查与复用

`operation=recipe`把用途数值规则绑定到已有候选，不改变UV布局。该manifest严格只允许`version / operation / scene / view_layer / objects / candidate / recipe`七个字段；顶层width、height、methods、constraints、margin_px、border_px、density_px_m、selection、action或pair_budget等布局/编辑字段均拒绝。配方内binding.width/height描述已有候选图幅，不能借绑定配方改图幅。

完整字段示例如下。`geometry`中的说明字符串必须替换为该对象候选record.geometry的真实64位小写十六进制值；这里不提供伪造的可执行哈希。对象、单位和图幅必须与当前候选一致，示例阈值仅说明格式，不是通用质量标准。

```json
{
  "version": "1.0",
  "operation": "recipe",
  "scene": "Scene",
  "view_layer": "ViewLayer",
  "objects": ["Product"],
  "candidate": "product_angle_based",
  "recipe": {
    "version": "1.0",
    "policy": {
      "name": "示例用途",
      "purpose": "按实际绘制用途审定",
      "reference": "填写真实依据；此字段不是经过认证的批准",
      "density_basis": "ISLAND_AREA_REFERENCE",
      "stretch_p95_max": 1.3,
      "stretch_max": 1.5,
      "density_relative_max": 0.05,
      "border_px_min": 8.0,
      "gap_px_min": 16.0
    },
    "binding": {
      "geometry": {"Product": "替换为当前候选该对象的真实geometry哈希"},
      "geometry_basis": "BASE_MESH",
      "unit_scale": 1.0,
      "width": 2048,
      "height": 2048
    }
  }
}
```

policy和binding均为完整、严格字段集合；recipe还可携带可选`usage_binding`，值必须为真实64位小写十六进制SHA-256。上例有意省略它：显式recipe操作会绑定当前mode和完整reuse_groups；density_basis=CONFIGURED_TARGETS时还绑定完整density规则。携带已有usage_binding的导入或请求若与当前规则不符，CONFLICT拒绝，不自动重绑。使用方式或复用组改变后，已有purpose_checks.usage_binding=mismatch、结果unknown（若同时存在实际违反则fail）；按指定密度的配方还会在目标/密度规则改变后失效。应重新审阅policy，再显式recipe绑定；经审阅省略旧usage_binding表示明确绑定当前规则，不是沿用旧批准。

名称、用途和依据须为非空文本；拉伸满足`1 <= stretch_p95_max <= stretch_max`，密度相对上限为0–1，图边和岛间像素值非负且图边必须留下可用图幅。geometry映射必须恰好覆盖候选对象；其指纹包含基础mesh和世界变换，另绑定unit_scale及候选W/H。换模型、世界变换、单位或图幅后，便携policy须重新审定并显式重新绑定；不能沿用旧binding或自动视为获批。导出的是已绑定配方及usage_binding，导入按完整配方校验，不自动迁移模型或放行改变后的用途。

当前`geometry_basis=BASE_MESH`，测量标记`measurement_surface=base_mesh / evaluated_surface=not_checked`。修改器、细分或其他最终求值表面未在此配方验证，基础网格通过不能宣称最终表面通过。`density_basis=ISLAND_AREA_REFERENCE`使用各岛像素面积/世界面积得到岛平均px/m，再相对`√(总像素面积/总世界面积)`比较；不测每个三角的局部密度一致性。旧配方始终沿用这个raw全岛均匀性依据，不因settings重点区而静默换门。

需要重点岛不同密度时，用户显式选择`density_basis=CONFIGURED_TARGETS`；它使用settings实际配置的全岛目标偏差，必须由区域/默认/原manifest回退覆盖全部岛。任意岛缺目标或configured测量不完整均unknown，不能以部分已配置岛通过。两种basis与用途检查实际采用值均保留在报告中。

候选原manifest若有显式`density_px_m`，`manifest_density_check`仍独立检查所有岛相对该绝对目标的最大偏差，阈值取当前配方density_relative_max或旧默认值；settings目标及recipe basis都不能绕过这个原目标门。需要替换原绝对目标，应copy_uv为新候选并显式设定新的创建参数，不在已有候选上假装目标已改。配置目标检查、raw均匀性和原manifest目标是不同证据，报告与面板不能互相冒充。

绑定后，validate和edit均沿用配方检查：基础硬检查、候选配方门和purpose_checks分开保留，任何用途超限使最终metrics.status=fail并阻止adopt；缺失测量、预算不完整或失效绑定为unknown，不算通过。绑定不匹配会拒绝显式绑定/adopt。旧的无recipe候选仍可按原候选默认边距/密度门编辑，purpose_checks显示not_assigned；它们不因此取得用途批准。adopt仅为采用编辑层与seam计划，数值通过也不替代棋盘、人工用途与视觉审阅。

面板“已生效”区域显示当前候选保存的配方和检查结果；下方字段是可编辑草稿，改变字段不会自动生效，须点击“按填写标准绑定并检查”。密度basis可显式选“按岛均匀”或“按指定密度”。切换候选会回填该候选的已绑定policy；无配方候选回填空名称及默认数值，不能把上一候选草稿当作新候选标准。检查unknown显示“检查未完成”，模型/单位/图幅或usage_binding失效须核对；“基础网格用途数值”和“最终求值表面尚未检查”分别呈现当前证据边界。TILED下图边/间距显示不适用，相关草稿字段禁用，不据此修改已保存阈值。

## 既有UDIM与贴图资源保护

当前只识别和保护既有UDIM，不制作UDIM。inspect给出材质消费者绑定：显式UVMap、活动渲染UV（含Texture Coordinate UV及Image Texture未连接Vector）、可解析Reroute/Node Group映射，并保留活动输出可达性与unknown；不凭节点名、坐标范围或整数格子猜意图。Blender图像source=TILED才是这里的UDIM图像证据；已确认使用的层或无法确定所用层的UDIM不能通过copy_uv导入，也不能edit/adopt覆盖。原层、tile列表、材质和渲染绑定保护不因新候选获批而解除；未解析的一般绑定也不能被报告为已经证明普通单图。

公共资源闭合读取已加载的强引用ID和`image.tiles`，外部UDIM只展开该列表明确列出的tile；每个外部成员须在resources中按绝对路径和expected_sha256声明并持锁校验。需要一个明确`<UDIM>`模板，不扫目录补猜tile；旁边额外文件不是自动成员。打包UDIM按tile逐项排除已自包含成员，混合打包/外部仍校验外部部分；另存将外部路径绝对化但保留模板与原tile列表。SEQUENCE/MOVIE、`<UVTILE>`以及不受支持的动态模板仍明确拒绝。资源校验通过只证明依赖闭合，不代表UDIM布局制作、消费者映射全覆盖或视觉批准。

## 异步状态与恢复

### M4 独立工作单元批量

`uv batch --params <JSON>`接收`{"manifest": {...}, "reuse_job": "可选的本jobs-dir旧批次ID"}`；`uv batch-resume --params <JSON>`接收`{"job_id": "旧批次ID"}`。后者严格沿用原清单；改变输入、配方、预算或对象时，用新的batch请求加reuse_job。全局`--jobs-dir`保持同一批作业根，`--timeout`是整批时间预算，step的timeout_seconds是单项上限；`--async`可后台提交，之后使用公共job wait/status/cancel/result。

manifest字段是`uv_batch_version="1.0"`、`policy`、`steps`。policy沿用公共pipeline的cpu_threads、memory_mb、disk_mb、gpu_mb、min_free_mb、failure（continue/fail_fast）预算，当前max_workers固定1。最多32项，超出需显式分批；不截断或自动放宽资源上限。每个step沿用id、command（仅uv.run/uv.inspect）、params、depends_on、bindings、limits、timeout_seconds、reuse。params就是单次UV请求，无隐式扫描或跨文件合并。

集合通过明确Scene/ViewLayer下的只读对象清单展开，再把确切目标名填入objects。同工程多对象联合图集放在一个uv.run步骤；独立步骤各自产生完整工作副本，不自动把它们的改动合并。跨工程文件分别处理，不维护实时关联图集。后续步骤要接续前一步候选，必须声明depends_on与`/candidate/file`到`/file`、SHA到`/expected_sha256`的绑定。

每项源、声明资源、实现与运行时、输出文件身份都核对；成功前仍要求独立重开和非目标保护。候选的metrics fail或unknown逐个隔离并保留报告。generate是替代候选集合：至少一个候选数值pass才将该步骤记为hard_pass_needs_review，usable_candidates明确列出可继续项；失败/unknown兄弟候选不被隐式选中，全部无可用候选才使步骤失败。普通单候选操作的fail/unknown不能通过。数值pass不代表新用途或视觉批准。只读inspect和采用/恢复等状态操作单独列示。部分失败返回非零退出码，`--compact`及pipeline-report.json仍列明成功项、失败项、uv_summary及产物；成功项不被覆盖。

恢复只复用证据完整、输入/实现/运行时/产物全部未变的成功项。失败项重新执行；源或资源仍携旧SHA时拒绝该项，显式更新SHA后的新请求重新计算；成功产物被手工改动时旧缓存失效，另开新子作业，保留手改文件。自动尝试有界，不承诺从原生求解中途续算。取消和超时沿用公共自有进程树管理，只作用于本批任务。

`--compact job status|cancel|wait|result <job_id>`保留完整报告链接。作业state与领域quality状态分别呈现；cancel_requested不是取消完成，需观察终态。终态的旧进度标last_progress。取消后保留诊断记录，重试使用新job，不承诺求解中间状态续算。

实际验证包括M1的source_open取消，以及M4批次第二项apply期间取消、四个已捕获自有进程退出和成功项恢复复用；M4本例取消到终态约0.389秒。保存中取消、任意原生长求解点和断电恢复未验，不能据此承诺普遍响应时间。既有UDIM的显式tile成员按上节保护和校验；序列/movie及未支持动态模板的拒绝不代表最终需求取消。
